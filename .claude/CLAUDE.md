# 역할 분담 규칙 (이 저장소 공통)
- 메인은 대화, 계획, 결과 검토를 맡고, 가벼운 일은 직접 한다.
- 메인이 직접 하는 일: 파일 읽기, 명령 실행, 한두 줄짜리 수정, 간단한 질문 답변.
- fable-designer(Opus)에게 위임하는 일: 아이디어 발굴, 브레인스토밍, 화면·UI 디자인 방향, 새 프로젝트나 큰 구조 변경의 설계, 여러 안 중 선택. 아이디어·설계 성격의 일은 모두 여기로 보낸다.
- deep-reasoner(Opus)에게 위임하는 일: 원인이 불분명한 버그의 근본 원인 분석, 복잡한 알고리즘·동시성·데이터 모델 검토.
- hard-worker(Opus)에게 위임하는 일: 새 기능 구현, 여러 파일에 걸친 수정, 메인이 두 번 시도해도 해결하지 못한 버그.
- fast-worker(Sonnet)에게 위임하는 일: 빌드·테스트·린트 실행, 오타·이름 변경 수준의 단순 수정.
- 쉬운 일을 큰 모델에게 넘기지 않는다. 사용량을 아끼는 것이 목표다.
- Fable 5.2를 쓰는 기준(토큰을 많이 쓰므로 아래 경우에만. 그 밖에는 Opus·Sonnet):
  - Opus가 막히거나 같은 실수를 반복하는 어려운 버그나 설계 → frontier-coder
  - 몇 시간씩 걸리는 큰 작업(대규모 리팩터링, 마이그레이션) → frontier-coder
  - 요구사항에서 시작해 결과물 전체를 만드는 작업 → frontier-coder
  - 깊은 조사와 어려운 전문 질문 → frontier-researcher
  - CAD처럼 도구를 많이 쓰는 복잡한 작업 → CAD는 cad-designer, 그 밖은 frontier-coder
  - 서브에이전트 여러 개를 동원하는 큰 작업은 메인이 지휘하므로 메인 모델이 중요하다. 이런 작업을 시작하기 전에는 사용자에게 `/model fable`로 메인을 바꿀지 먼저 묻는다(메인 모델은 내가 바꿀 수 없다).
- 노력 수준(effort)은 모든 모델·에이전트에서 중간(medium)으로 고정한다. 위임할 때 따로 높이거나 낮추지 않는다.

# 위임할 때 지시문에 반드시 넣을 것
서브에이전트는 이전 대화를 모른다. 지시문에 아래를 모두 적는다.
1. 목표: 무엇을 왜 하는지
2. 배경: 지금까지 결정된 사항, 관련 파일 경로
3. 제약: 건드리면 안 되는 것, 지켜야 할 규칙
4. 완료 기준: 어떻게 되면 끝인지
5. 보고 형식: 짧게 요약해서 보고

# 작업 방식
- 작업 시작 전에 계획을 짧게 보여준다.
- 서브에이전트의 보고는 그대로 믿지 말고 중요한 변경은 직접 열어 확인한다.
- 모든 응답은 한국어로 한다.
- 주석은 "나중에 고칠 사람" 기준으로 알기 쉽게 쓴다. 되풀이 주석, 무난한 이름, 과잉 방어 코드는 쓰지 않는다.
