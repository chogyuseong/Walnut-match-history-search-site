# 이 저장소의 작업 규칙

이 파일과 `.claude/agents/`, `.claude/settings.json`은 git에 올라가 있어 클론하면 그대로 적용된다.
이 저장소 안에서는 이 규칙이 개인 전역 규칙(`~/.claude/CLAUDE.md`)보다 우선한다. 특히 "effort는 medium 고정" 같은 전역 규칙은 아래 "모델 사용 규칙"으로 바꿔 읽는다.
화면 디자인 규칙은 저장소 맨 위 `CLAUDE.md`에 따로 있다.
원래 설정 요청문은 `model-setup-prompt.md`(2026-11-11, claude.dev 글 "Which Claude model should you build with?" 2026-11-09 기준)다.

## 모델 사용 규칙

### 기본값
- 메인 작업은 Opus 5.5, effort medium으로 진행한다.
- 모델과 effort는 Claude가 스스로 바꿀 수 없다. 아래 기준에 해당하면 작업을 시작하기 전에 "이 작업은 ○○ 모델 / ○○ effort를 권장합니다"라고 먼저 알리고 사용자의 결정을 기다린다. 단, 막힌 작업자의 effort를 high로 올리는 것은 묻지 않고 하고 알리기만 한다(아래 "실패했을 때 올리는 순서").

### 작업별 권장 모델
| 작업 종류 | 권장 모델 | 권장 effort | 예시 |
|---|---|---|---|
| 범위가 명확한 구현 | Sonnet 5.5 | medium | 정해진 항목 구현, 알려진 버그 수정, 문구·스타일 수정 |
| 일반 코딩·판단이 섞인 작업 (기본) | Opus 5.5 | medium | 새 기능 추가, 원인이 불분명한 버그, 여러 파일에 걸친 수정 |
| 어려운 작업 | Opus 5.5 | high | 성능 최적화, 데이터 구조 변경, 복잡한 전적·MMR 계산 로직 |
| 큰 작업의 지휘, 구조 전체·대규모 마이그레이션 결과 검토 | Fable 5.2 | medium → high | 작업자 여러 명을 쓰는 작업의 계획·지시서·결과 검토, v2 구조 전체 검토, 대규모 마이그레이션 결과 검토 |
| 단순·대량 보조 작업 | Haiku 5.5 (서브에이전트 전용) | medium | 파일 찾기, 로그 읽기, 테스트 결과 요약 |

- Fable 5.2가 맡는 일은 두 가지뿐이다(2026-11-11 사용자 결정). ① 작업자 여러 명을 쓰는 큰 작업의 지휘: 계획, 작업 지시서, 결과 검토, 배포 판단. ② v2 구조 전체나 대규모 마이그레이션 결과 검토.
- Fable은 코드를 직접 고치지 않는다. 구현은 Opus 작업자(`hard-worker`)가 한다. 지휘가 필요한 작업을 시작하기 전에 메인을 `/model fable`로 바꿀지 사용자에게 묻고, 지휘가 끝나면 Opus로 내리자고 알린다.
- 지휘가 필요 없는 일상 작업(작은 수정, 질문, 한 사람이 끝낼 구현)은 메인 Opus medium으로 한다.
- 스펙이 명확해도 D1 마이그레이션이나 성능 최적화는 Sonnet으로 내리지 않는다.
- 판단과 설계는 상위 모델, 반복적이고 검증이 쉬운 작업은 하위 모델에 맡긴다.

### 실패했을 때 올리는 순서
작업이 실패하거나 같은 실수를 반복하면 모델을 바로 올리지 말고 이 순서를 따른다.
1. 자체 검증 수단을 먼저 만든다(테스트, 빌드, 로컬 실행 `npm run dev`, API 호출 스크립트 등).
2. effort를 한 단계 올린다. 작업자(서브에이전트)에게 맡긴 일이 막히면 묻지 않고 그 작업만 high로 올려 다시 맡기고, 올렸다는 사실과 이유를 사용자에게 알린다(2026-11-11 사용자 허락). 어려운 부분이 끝나면 다음 작업부터 medium으로 돌아간다. 메인의 effort는 Claude가 바꿀 수 없으므로 올릴 때와 내릴 때를 사용자에게 알린다.
3. 그래도 안 되면 다음 상위 모델로 올리자고 제안하되, 더 낮은 effort에서 시작한다(예: Sonnet에서 실패 → Opus medium). Opus high로도 실패하면 구현을 Fable에게 넘기지 않고, 막힌 지점과 시도한 것을 정리해 사용자에게 알리고 결정을 기다린다.
- 모델이 모르는 지식·기술 문제는 effort로 해결되지 않으므로 2단계를 건너뛰고 3단계로 간다.

### 모델 전환 시 주의
- 캐시는 모델별로 따로라서, 모델을 바꾼 첫 턴은 대화 전체의 캐시 비용을 다시 낸다. 바꾸기 전에 `/compact`를 먼저 하자고 알린다.
- 상위 모델에서 하위 모델로 내리면 이전 추론 내용이 사라질 수 있다. 전환 전에 지금까지의 결정 사항을 3~5줄로 요약해 둔다.

### 대화 관리
- 할 일 묶음(5~10개)이 끝날 때마다 결과를 요약하고 멈춘다. 다음 묶음은 `/clear` 후 새로 시작한다.
- 긴 작업을 이어갈 때는 `/compact`를 쓴다.

### 웹 화면 수정 규칙 (최우선)
- 화면(HTML/CSS/JS)을 수정하면 항상 모바일 폭(360~430px)에서도 깨지지 않는지 확인한다(가로 넘침, 낱말 중간 줄바꿈, 하단 탭에 가리는 버튼, 44px 터치 영역).
- 확인 방법과 결과를 작업 요약에 반드시 적는다.

## 서브에이전트 규칙
- 메인이 Opus일 때 직접 하는 일: 코드 편집, 설계 판단, 버그 원인 판단.
- 메인이 Fable일 때(지휘): 계획·지시서·검토·배포만 하고 코드 편집은 `hard-worker`(Opus)에게 맡긴다. 규칙 문서 같은 한두 줄 수정만 직접 한다.
- 작은 모델(Haiku)에 맡기는 일: 파일 찾기(`Explore`), 테스트·빌드 로그 읽기(`log-reader`), Cloudflare 요청 위치 조사(`usage-checker`)처럼 실수가 있어도 쉽게 알아챌 수 있는 일.
- 모델을 정하지 않은 서브에이전트는 sonnet으로 돈다(`.claude/settings.json`).
- 서브에이전트가 보고한 파일 위치·내용은 그대로 믿지 말고, 편집 전에 메인이 해당 파일을 직접 열어 확인한다(작은 모델이 잘못 읽으면 메인이 엉뚱한 파일을 열어 토큰을 더 쓴다).
- 서브에이전트의 토큰은 그 서브에이전트 모델 요금으로 계산되고, 사용 한도에도 함께 들어간다.

### 그 밖에 남겨 둔 서브에이전트 (사용자가 요청하거나 아래 경우에만)
- `fable-designer`(Opus): 아이디어·화면 디자인 방향·여러 안 중 고르기. 파일을 고치지 않는다.
- `deep-reasoner`(Opus): 원인이 불분명한 버그의 근본 원인 분석, 동시성·데이터 모델 검토.
- `hard-worker`(Opus): 지휘(Fable)가 맡기는 구현 전부, 또는 메인 대화와 별도로 오래 걸리는 구현을 나란히 돌려야 할 때.
- `fast-worker`(Sonnet): 빌드·테스트·린트 실행, 오타·이름 바꾸기 수준.
- `frontier-coder`·`frontier-researcher`(Fable 5.2): 메인이 Opus인 채로 큰 작업의 계획·지시서나 구조 전체·대규모 마이그레이션 결과 검토를 받아야 할 때, 또는 사용자가 Fable을 직접 지정할 때만. 의견과 지시서만 받고 구현은 Opus가 한다.

### 위임할 때 지시문에 반드시 넣을 것
서브에이전트는 이전 대화를 모른다. 지시문에 아래를 모두 적는다.
1. 목표: 무엇을 왜 하는지
2. 배경: 지금까지 결정된 사항, 관련 파일 경로
3. 제약: 건드리면 안 되는 것, 지켜야 할 규칙
4. 완료 기준: 어떻게 되면 끝인지
5. 보고 형식: 짧게 요약해서 보고

## 작업 방식
- 작업 시작 전에 계획을 짧게 보여주고, 단계마다 예상 시간을 적는다.
- 모든 응답과 문서는 한국어로 한다.
- 주석은 "나중에 고칠 사람" 기준으로 알기 쉽게 쓴다. 되풀이 주석, 무난한 이름, 과잉 방어 코드는 쓰지 않는다.
- 비밀값(`SESSION_SECRET`, `PASSWORD_PEPPER`)과 복구 코드는 저장소에 적지 않는다. 비밀번호 관리자 'naejeon 운영' 항목에 둔다(`배포-이어하기.txt`).
