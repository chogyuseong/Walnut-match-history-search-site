# 서버 보안 감사와 수정 (2026-11-10)

운영 배포 직전에 한 보안 감사(코드 읽기 + `npm audit`)와 그 수정이다. 같은 날 앞서 한 감사(커밋 9690142)의 후속이다. 기준은 같다: Cloudflare **무료 요금제**(요청당 CPU 10ms, D1 하루 읽기 500만 행·쓰기 10만 행, Worker 요청 하루 10만 건), 자체 계정 로그인만.

사용자 결정: 요금제는 무료 유지, 가입 코드(누구나 가입하지 못하게 막기)는 도입하지 않는다, 처리방침 연락처는 전화번호와 이메일 둘 다 둔다.

## 1. 요약

- 정보 유출·권한 탈취 쪽에서 배포를 막을 결함은 찾지 못했다(6절 확인함).
- 높음 2건은 가용성이다: 한도 안의 요청만으로 D1 하루 읽기·쓰기 한도를 바닥낼 수 있었다. 이번 수정은 **한 주체(한 계정·한 IP·한 조회 링크)가 혼자 다 쓰는 것**을 막는다. IP를 여러 개 쓰는 사람까지는 무료 요금제에서 막지 못한다(5절).
- 새 비밀값 `PASSWORD_PEPPER`가 필요하다. 넣지 않고 배포하면 모든 API가 503(`CONFIG_ERROR`)이다.

## 3. 새 설정

비밀값(환경마다 `wrangler secret put … --env …`): `PASSWORD_PEPPER`(32자 이상, `SESSION_SECRET`과 다른 값).

vars(`wrangler.jsonc`, 배포안내 11절):

| 값 | 운영 | 뜻 |
|---|---|---|
| `RATE_STRIKES_PER_IP_DAY` | 20 | IP 하루 벌점 한도 |
| `RATE_SNAPSHOT_ROWS_PER_ACCOUNT_DAY` | 3,000,000 | 스냅숏 하루 읽기 예산(계정) |
| `RATE_SNAPSHOT_ROWS_PER_IP_DAY` | 4,000,000 | 같은 예산(IP) |
| `RATE_SNAPSHOT_ROWS_PER_TOKEN_DAY` | 4,000,000 | 같은 예산(조회 링크 = 모임) |

코드에 고정: 아이디별 하루 실패 200번, 그 뒤 15분에 5번(`local.ts`), 비밀번호 최소 10자(`shared/account.ts`).

## 4. 값을 이렇게 잡은 까닭

- **스냅숏 예산**: 정상 사용 추정은 [개선-경험-설계-2026-11-10](개선-경험-설계-2026-11-10.md) B-1(저녁 6경기, 보는 사람 10명)의 100경기 모임 약 40만 행, 522경기 모임 약 200만 행이다. IP·조회 링크 400만은 100경기 모임에 10배, 522경기 모임에 2배다. **큰 모임에 10배 여유는 줄 수 없다**: 정상 사용이 이미 하루 한도의 40%라, 10배(2천만 행)면 예산이 한도(500만)보다 커서 아무것도 막지 못한다. 400만은 "한 주체가 혼자서는 하루 읽기를 다 쓰지 못한다"는 선에서 가장 넓은 값이다. 계정 300만은 운영자 한 사람의 저녁 몫(저장마다 다시 읽기 200, 약 100번 × 7천 행 = 70만 행)의 4배다.
- **IP 벌점 20**: PC방·같은 와이파이로 여럿이 한 IP를 나눠 쓰는 저녁에 분 단위 한도에 몇 번 걸리는 것은 정상이다. 20개 창은 그보다 훨씬 많다.
- **하루 실패 200**: 15분 한도(100)의 두 창 분량. 주인이 비밀번호를 여러 번 틀리는 정도로는 닿지 않는다.

## 5. 남은 위험(고치지 못한 것)

1. **한도 아래로만 보내는 익명 요청의 쓰기**(H2의 나머지). 벌점은 한도를 넘긴 창에서만 쌓인다. 한 IP가 로그인 실패 10·가입 5·복구 5·없는 조회 토큰 30·화면 오류 보고 10을 매분 한도 바로 아래로 보내면 여전히 분당 약 200행(카운터, 실패 기록, 오류 기록 넣기·지우기)을 쓴다. 약 8시간이면 10만 행이다. 이번 수정으로 없어진 것은 "아무 POST나 보내면 되는" 가장 싼 길(분당 약 125행)이다. 더 막으려면 익명 요청에 IP별 하루 상한(요청마다 쓰기 1행이 더 든다)이나 사이트 전체 하루 상한(넘으면 로그인 없는 요청만 거절)을 둬야 한다. 정상 사용자를 막을 수 있는 설계 결정이라 이번에는 넣지 않았다.
2. **IP를 바꿔 가며 쓰는 사람**. IP별 예산·벌점은 IP마다 따로다. IPv6는 /64 단위로 묶지만 /48을 가진 사람은 /64를 6만 개 쓸 수 있다. 스냅숏 예산도 계정 2개 + IP 2개면 하루 읽기에 닿는다(가입이 열려 있다).
3. **Worker 요청 하루 10만 건**. 코드로 막을 수 없다(초당 1.2건이면 닿는다).
4. 1~3 모두 자체 도메인 + WAF 속도 제한 규칙이나 Workers Paid로 풀린다. 무료 유지가 사용자 결정이므로, D1 사용량과 `#/admin`의 한도 걸림을 주 1회 본다.
5. **아이디 잠금**: 누가 일부러 한 아이디에 하루 200번 넘게 틀리면 그날 주인도 15분에 5번(공격자 몫 포함) 실패 뒤에는 기다려야 한다. 추측을 줄인 대가다. 급하면 `auth_failures`의 `day:` 행을 지운다.
6. **스냅숏 비용 자체**: 예산을 넓히려면 응답 본문 캐시(`snapshot.ts` snapshotBody의 확장 자리)가 먼저다. 같은 자료를 보는 사람 10명이 한 번 만든 본문을 나눠 쓰면 정상 사용이 10분의 1로 준다.
7. 평문 토큰(조회 링크, 참가 신청 링크 원문, 요청 기록의 새 조회 토큰 14일)은 다시 복사 기능 때문에 그대로 둔다. staging에 실자료를 복원했다면 시험 뒤 그 모임을 지운다(staging은 실행 기록이 켜져 토큰이 로그에 남는다).
8. U+200D를 지우므로 이름·메모의 조합 이모지(가족·깃발)는 낱개로 풀린다.

## 6. 확인함(문제 없음, 다시 볼 필요 없는 것)

- 인증·세션: 쿠키 속성, HMAC 서명 + 만료 + 세션 세대, 로그아웃·비밀번호 변경·복구·탈퇴 때 무효화, 세션 쿠키와 OAuth state 쿠키를 서로 바꿔 쓸 수 없음, 복구 코드 160비트·해시 저장·상수 시간 비교·일회용, 없는 아이디와 같은 응답·계산량, IPv6 /64 묶음.
- 권한: 모든 `/api/groups/:gid/*`가 `requireOperator`/`requireOwner`, 대표 전용 경로 구분, 멤버 경로 분리, 자원 ID가 모두 `group_id` 조건이나 모임 범위 읽기 뒤에만 쓰임, 복원의 다른 모임 ID 충돌 검사, 토큰 128비트·해시(인수·초대·연결)·24시간·일회용, 조회 응답의 비공개 값 제외.
- 입력: SQL의 `${}`는 모두 코드 상수이고 사용자 값은 bind, 본문 크기 상한(스트림), `assertOnlyKeys`, 백업 검증, CSV 수식 주입 방지, 화면에 `dangerouslySetInnerHTML` 없음.
- SSRF: ID만 뽑아 주소를 조립, 리디렉션 수동 3번·허용 호스트·https, 크기·시간·Content-Type 제한.
- 헤더·전송: CSP(`script-src 'self'`), 프레임 금지, HSTS(운영), CORS 헤더 없음, Origin 확인 + JSON 강제, API 기본 `no-store`, ETag에 역할·계정·토큰, 권한 확인이 304보다 먼저.
- 배포: 저장소에 비밀값 없음, 가짜 로그인·테스트 훅은 세 조건이 모두 맞아야 열림, 오류 응답에 스택·SQL 없음, 로그에 토큰·개인정보 없음, 운영 실행 기록 끔.
- 개인정보: 이메일·실명 없음, IP·아이디는 해시만, 백업에 계정·토큰·연결·신청 없음, 모임 삭제 때 R2 백업 삭제.
- 의존성: `npm audit --omit=dev` 0건.
- 9690142의 여섯 수정(한도 초과 뒤 쓰기 중단, 흔한 비밀번호 거절, 운영 실행 기록 끄기, 공동 운영자 내보낸 뒤 링크 안내, 오류 기록 출처별 한도, CF-Worker)은 CF-Worker(M2로 다시 고침) 말고 그대로 맞다.

## 7. 배포 전에 할 일

1. `npx wrangler secret put PASSWORD_PEPPER --env staging`, `--env production`(각각 새로 만든 값, `SESSION_SECRET`과 다르게).
2. staging의 시험 계정은 페퍼가 달라져 로그인되지 않는다. 다시 가입한다.
3. 세션 쿠키 이름이 바뀌어 기존 로그인은 모두 풀린다.
4. 기존 기록 이전이 끝나면 `RATE_BULK_ROWS_PER_ACCOUNT`·`_PER_IP`를 500~1000으로 낮춘다.
