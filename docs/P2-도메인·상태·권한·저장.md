## 0. 입력과 표기

- [사실] P1 결정 요청에 "다음"으로 답해 기본값이 채택됐다: A 채택(기본 "같은 팀·포지션 재무작위"), B 채택(최소 형태), C 링크·텍스트 채택, D 채택(축소), 활성 운영자 1명, 서포터 순환 v1 포함.

- 구현·테스트는 미수행이다. 아래 "검증"은 P4에서 수행할 방법을 뜻한다.

## P2-1. 엔티티

| 엔티티 | 식별자와 핵심 속성 | 메모 |
|---|---|---|
| 계정 | 계정 ID, 로그인 수단의 고유값 | 운영자만 필요하다. 비밀번호 없음 |
| 모임 | 모임 ID, 이름, 표시 시간대, 현재 설정 버전, **진행 상태 버전**, 조회 토큰 | 모든 하위 레코드가 모임 ID를 가진다 |
| 권한 | (모임, 계정, 역할=운영자) | 모임당 활성 운영자 1행. 조회자는 계정이 아니라 조회 토큰으로 구분한다 |
| 참가자 | 참가자 ID(모임 내), 표시 이름, 실력 그룹(1~4 또는 미지정), 상태(활성·보관) | 이름은 속성이다 |
| 내전 세션 | 세션 ID, 시작 시각(UTC), 종료 시각, 표시 날짜 | 날짜 문자열과 별개다 |
| 경기 | 경기 ID, 모임 내 경기 번호, 세션 ID, 상태, 시작·종료·경기 시각(UTC), 승리 팀(A/B/없음), **팀 A의 진영**(블루/레드/미상), 적용 설정 버전, 출처(실시간·지난 경기 입력·이관), **경기 버전** | 결과는 경기에 붙는다 |
| 경기 확정 명단 | (경기 ID, 참가자 ID), 팀(A/B), 포지션 | 경기당 10행. 시작 뒤에는 정정으로만 바뀐다 |
| 변경 이력 | 경기 ID, 순번, 종류(결과·정정·제외·복구·취소), 항목별 이전·이후 값, 시각 | 추가만 가능 |
| 순환 주기 | 주기 ID, 세션 ID, 상태(활성·종료) | 세션당 활성 1개 |
| 순환 사건 | 주기 ID, 경기 ID, 참가자 ID, 종류(사용·반복 허용), 무효 표시 | 사람 기준 |
| 설정 버전 | 버전 ID, 전체 설정 스냅샷(그룹 가중치, 비교 순서, 칭호 구간, 순환 사용 여부, 공개 정책) | 수정하지 않고 새 행을 만든다 |
| 요청 기록 | (모임, 요청 ID), 작업, 내용 해시, 응답, 시각 | 중복 저장 방지용 |
| 초안 | **기기에 보관**. 참가자·팀·포지션·고정 조건·추첨 기록, 형식 버전, 기준 진행 상태 버전 | 서버에 저장하지 않는다(아래 설명) |

### 초안을 기기에만 두는 이유

해법 비교:
1. 문구: 해당 없음.
2. 통합: 초안을 서버 엔티티로 만들지 않는다. "이 팀으로 시작" 요청이 명단 전체를 싣고 가고 서버가 처음부터 검증한다. ← 선택
3. 새 상태: 서버에 초안 행과 자동 저장, 초안 충돌 처리를 둔다.

선택 근거: 서버에 초안이 없으면 "초안과 현재 경기 분리"가 구조적으로 성립하고, 초안 자동 저장·충돌 규약 전체가 사라진다. 포기한 것: 휴대폰에서 짠 초안을 PC에서 이어 쓸 수 없고, 브라우저 저장소가 지워지면 초안을 다시 짜야 한다. 잃는 것은 편성 1~2분이며 기록은 아니다.

반대: 내장 브라우저(카카오톡·디스코드)는 저장소가 쉽게 비워진다. → 답: 운영자 화면은 로그인이 필요해 일반 브라우저에서 열도록 안내한다. 관찰에서 초안 유실이 반복되면 서버 초안으로 올린다(결정 요청 4).

### 참가자 처리

- 동명이인: 활성 참가자의 정규화한 이름(앞뒤 공백 제거, 연속 공백 1개, 대소문자 무시)은 모임 안에서 유일하다. 같은 이름은 "민수(탑)"처럼 구분해 넣도록 안내한다.
- 이름 변경: 속성만 바뀐다. 과거 경기는 현재 이름으로 보이고, 이미 복사된 텍스트는 바뀌지 않는다.
- 중복 참가자: 입력 시 비슷한 이름을 제안해 예방한다. 이미 생긴 중복을 합치는 화면은 후속이며, v1에서는 서비스 운영자가 백업 후 수동으로 처리한다(두 사람이 같은 경기에 있으면 합칠 수 없다).
- 탈퇴: "보관"(선택 목록에서 숨김, 기록 유지)과 "이름 지우기"(이름을 "참가자 #번호"로 교체, 기록 유지)를 구분한다.
- 계정 연결·해제, 사칭: v1에는 참가자 계정이 없다. 기기에서 고른 "내 이름"은 표시 편의이며 소유권이 아니다. 후속에서 연결 표를 추가할 수 있도록 참가자 ID만 안정적으로 유지한다.
- 모임 간 분리: 참가자·그룹·기록은 모임마다 따로다. 다른 모임의 평가를 읽는 경로가 없다.

### 세션·팀·설정

- 세션은 첫 경기 시작 때 열리고, 운영자가 "오늘 내전 마치기"를 누르면 닫힌다. 마지막 활동 뒤 12시간이 지나 새 경기를 시작하면 "새 내전 / 이어가기"를 묻는다(기본: 새 내전). 자정은 세션을 나누지 않는다. "오늘" 통계는 **가장 최근 세션**을 뜻한다.
- 팀은 A/B가 식별자다. 화면 좌우와 색은 기기 표시 설정이며 저장하지 않는다. 진영은 "팀 A의 진영" 한 칸으로만 저장하므로 팀 B의 진영은 항상 그 반대다.
- 설정 버전은 병합이 아니라 전체 스냅샷이다. 값이 한 번도 저장되지 않은 것(기본값 적용)과 빈 값으로 저장된 것(빈 채로 유지)을 구분하며, 빈 값 뒤에 이전 버전의 값을 다시 읽지 않는다.

## P2-2. 상태 전환

삭제는 별도 상태로 두지 않는다. 화면의 "삭제"는 **전적 제외**(복구 가능)다. 영구 삭제는 모임 삭제에만 있다.

```
[기기 초안] --시작--> 진행 중 --종료·결과 나중에--> 결과 입력 대기
                        |                               |
                        +--------결과 확정-------------+--> 결과 확정
                        |                               |
                        +--------미진행 취소-----------+--> 취소
                                  결과 입력 대기·결과 확정 --전적 제외--> 제외 --복구--> 이전 상태
[지난 경기 입력] ---------------------------------------------> 결과 확정
```

버전 검사 범위는 세 가지다: **진행 상태 버전**(세션·진행 중 경기·순환 주기), **경기 버전**(해당 경기 하나), **설정 버전**.

| 전환 | 원본 변경 | 재생성되는 결과 | 버전·충돌 검사 |
|---|---|---|---|
| 시작 | 경기 1행, 명단 10행, 순환 사건(순환 켜짐일 때 양팀 서포터), 적용 설정 버전 기록. 세션이 없으면 생성 | 현재 경기 화면, 순환 후보, 조회 링크 내용 | 진행 상태 버전, 설정 버전 |
| 종료·결과 나중에 | 종료 시각, 상태 | 홈의 "결과 미입력 N경기" | 경기 버전, 진행 상태 버전 |
| 결과 확정 | 승리 팀, 팀 A의 진영, 확정 시각, 이력 1행 | 모든 통계, 배치 판수, 칭호, 오늘의 결과 | 경기 버전 |
| 미진행 취소 | 상태, 해당 경기 순환 사건 무효 표시, 이력 1행 | 순환 후보 | 경기 버전, 진행 상태 버전 |
| 전적 제외 | 상태, 이력 1행. 순환 사건은 그대로 | 통계, 배치, 칭호 | 경기 버전 |
| 복구 | 제외 직전 상태로, 이력 1행 | 통계, 배치, 칭호 | 경기 버전 |
| 정정 | 지정한 항목, 이력 1행 | 영향받는 통계 | 경기 버전 |
| 지난 경기 입력 | 결과 확정 경기 1행과 명단. 세션·순환·진행 상태는 건드리지 않음 | 통계, 배치, 칭호 | 설정 버전만 |

- **시작은 한 요청·한 트랜잭션이다.** 검증 순서: 권한 → 요청 ID 조회 → 진행 상태 버전 → 참가자 10명이 이 모임의 활성 참가자이고 서로 다름 → 팀당 5명 → 포지션 5종이 팀마다 하나씩 → 순환 재검사 → 저장. 하나라도 실패하면 아무것도 남지 않는다.
- 진행 중 경기가 있을 때 시작을 누르면 "결과 입력 / 결과는 나중에 입력하고 시작"을 묻는다. 뒤쪽을 고르면 같은 요청이 이전 경기를 대기로 옮기고 새 경기를 시작한다.
- 응답을 받지 못하면 같은 요청 ID로 조회해 결과를 확인한다.
- 미진행 취소로 차례를 돌려받은 사람이 같은 주기의 뒤 경기에서 "반복 허용"으로 서포터를 했다면, 그 사건을 일반 사용으로 바꿀지 묻는다(기본: 바꾼다).

### 동시 진행 제한

| 대상 | 제한 | 이유 |
|---|---|---|
| 열린 세션 | 모임당 1 | 지인 모임은 한 번에 한 판만 한다 |
| 진행 중 경기 | 모임당 1 | 조회 링크의 "현재 경기"가 하나로 정해진다 |
| 결과 입력 대기 | 모임당 10 | 하루 최대 8경기 가정보다 크다. 넘으면 시작을 막고 대기 목록을 보여준다 |
| 초안 | 기기당 1 | 다음 경기는 하나뿐이다 |

반대: 10명이 넘는 모임은 두 판을 동시에 돌릴 수 있다. → 답: 범위 밖(출전 기회 배분 없음)이며 규모 가정과 맞지 않는다. 수요가 확인되면 "진행 중 1"만 설정값으로 바꾸면 된다.

## P2-3. 불변식과 보장 위치

| 불변식 | DB 제약 | 서버 트랜잭션 | 클라이언트 안내 |
|---|---|---|---|
| 확정 경기는 서로 다른 10명 | 명단 기본 키 (경기, 참가자) | 정확히 10행인지 확인 | 인원 8/10 표시 |
| 팀당 5명 | — | 팀별 5행 확인 | 팀별 인원 표시 |
| 팀 내 포지션 중복 없음 | 유일 (경기, 팀, 포지션) | 실시간 경기는 포지션 필수. 지난 경기·이관은 빈 포지션 허용 | 중복 포지션 강조 |
| 알려진 진영은 팀과 일대일 | 진영을 "팀 A의 진영" 한 칸으로 저장 | — | — |
| 다른 모임 데이터 연결 불가 | 명단이 (모임, 참가자)를 함께 참조하는 복합 외래 키. 모든 표에 모임 ID | 모든 조회·쓰기에 인증된 모임 조건 | — |
| 초안과 현재 경기 분리 | 서버에 초안 없음 | 시작 시 값 복사 | 초안 화면에 결과 버튼 없음 |
| 같은 확정 의도는 한 번만 저장 | 유일 (모임, 요청 ID) | 같은 ID·같은 내용 → 저장된 응답 반환. 같은 ID·다른 내용 → 거절 | 요청 ID는 확인 창을 열 때 만들고 재시도에 재사용 |
| 무권한 요청은 아무것도 바꾸지 않음 | — | 권한 검사가 트랜잭션보다 먼저 | 역할별 화면 숨김(보안 수단 아님) |
| 같은 명단·같은 승패의 새 경기는 저장됨 | 내용 기준 유일 제약 없음 | 중복 판단은 요청 ID만 | — |
| 모임당 활성 운영자 1명, 진행 중 1경기 | 조건부 유일 색인 | 버전 검사 | — |
| 한 주기에서 한 사람의 "사용"은 1회 | 조건부 유일 (주기, 참가자) — 종류=사용, 무효 아님 | 시작 시 재검사 | 후보 목록 |

요청 기록 보존: **14일**. 규모 가정상 주당 약 3,000건, 14일 약 6,000행으로 용량 부담이 없다. 보존 기간이 지난 재전송은 요청 ID로 걸러지지 않지만 진행 상태 버전·경기 버전 검사가 거절한다. [검증 필요] 행 수는 가정에서 계산한 값이다.

반대: 팀당 5명을 DB 제약으로 걸지 않으면 버그가 뚫을 수 있다. → 답: 맞다. 명단 쓰기 경로를 "시작"과 "지난 경기 입력"과 "참가자 정정" 세 함수로 제한하고, 통합 테스트에서 직접 삽입 경로가 없음을 확인한다. 지연 제약 트리거는 P4에서 스택에 따라 판단한다.

## P2-4. 초안 보호와 복귀

| 구분 | 위치 | 화면 문구 |
|---|---|---|
| 서버 확정 데이터 | 서버 | "저장됨 · 오후 9:12 확인" |
| 편집 중 초안 | 기기 저장소 | "이 기기에만 있어요" |
| 초안의 기준 버전 | 초안 안에 기록 | 표시하지 않음. 충돌 판단에만 사용 |

- 서버 조회는 화면 복귀, 수동 새로 고침, 진행 중 화면의 긴 주기 확인에서만 한다. 실시간 통신은 쓰지 않는다.
- 조회 결과는 초안을 덮어쓰지 않는다. 진행 상태 버전이 초안의 기준과 다르면 초안을 유지한 채 알린다: "다른 기기에서 경기가 시작됐어요. 작성 내용은 그대로 두었습니다. 현재 경기를 확인해 주세요." 과거 경기 정정 같은 관련 없는 변경은 알리지 않는다.
- 결과 입력 창을 연 채 그 경기의 경기 버전이 바뀌면: "이 경기 명단이 수정되었습니다. 선택한 내용은 유지했어요. 최신 명단을 확인해 주세요."
- 돌아왔을 때: 진행 중 경기가 있으면 그 화면, 초안이 있으면 "작성하던 편성이 있어요 — 이어서 / 버리기", 대기 경기가 있으면 "결과 미입력 N경기".
- 기준 버전이 오래된 초안은 자동으로 보내지 않는다. 사용자가 시작을 누르면 서버가 현재 상태로 다시 검증한다.
- 기기 저장소 쓰기가 실패하면 "이 기기에 편성을 보관할 수 없어요. 창을 닫으면 사라집니다"를 표시하고 작업은 계속한다.

운영자가 1명이므로 여러 기기 문제는 위 갱신 감지와 초안 보존으로 처리하고, 실시간 편집은 넣지 않는다.

## P2-5. 서포터 순환

### 해법 비교

| | ① 예약 엔티티 + 6개 무효화 키 | ② 예약 없이 매번 재계산 | ③ 중간 |
|---|---|---|---|
| 방식 | 서버가 추첨 결과를 예약으로 저장하고 조건 변경마다 무효화 | 추첨은 초안의 포지션 교환일 뿐. 현재 서포터와 오늘 이력을 비교해 충돌만 표시 | 서버는 ②와 같다. 기기 초안에 팀별 추첨 기록과 작은 지문을 둔다 |
| 복잡도 | 높음. 서버 초안이 전제되고 무효화 누락이 버그가 된다 | 낮음 | 낮음~중간. 추가 상태가 기기 안에만 있다 |
| 검증 가능성 | 무효화 조합이 많아 사례 수가 폭증 | 순수 함수 하나 | 서버는 순수 함수, 지문 비교는 단위 테스트 |
| 사용자 설명 | "예약됨·무효·만료" 상태를 설명해야 함 | 재클릭마다 결과가 바뀔 수 있어 "다시 뽑으면 되네"가 된다 | "뽑은 결과 유지 / 다시 확인 필요" 두 가지 |
| 요구 충족 | 전부 | 재클릭·새로고침 동일 결과, 영향받은 팀만 재확인을 충족하지 못함 | 전부 |

**선택: ③.** ②는 요구 두 개를 놓치고, ①은 P2-1에서 버린 서버 초안을 되살린다.

### 동작

- **지문**(팀별): 팀 5명의 참가자 ID, 추첨 전 서포터, 그 팀의 포지션 고정 조건, 주기 ID, 주기의 유효 사건 수. 표시 이름·좌우·진영·표시 설정은 들어가지 않으므로 바뀌어도 영향이 없다.
- 추첨을 누르면: 지문이 같은 기록이 있으면 그 결과를 다시 보여준다. 없으면 후보(팀 5명 중 이번 주기에 사용 사건이 없고 다른 포지션에 고정되지 않은 사람)에서 한 명을 뽑아 기존 서포터와 포지션만 맞바꾸고 전후를 이름으로 보여준다: "김용호 미드→서포터, 조규성 서포터→미드, 나머지 유지".
- 초안이 바뀌면 지문이 달라진 팀만 "다시 확인 필요"가 된다. 되돌리기로 초안이 복원돼도 지문을 현재 이력과 다시 비교하므로 무효가 된 추첨은 되살아나지 않는다.
- **차례 소비는 시작 요청에서만** 일어난다. 서버는 기기의 추첨 기록을 믿지 않고, 받은 명단의 양팀 서포터를 현재 주기 이력과 대조한다. 이미 사용한 사람이 서포터이고 요청에 반복 확인 표시가 없으면 거절하고 누구인지 알려준다. 확인 표시가 있으면 "반복 허용" 사건으로 남긴다. 무작위 배정으로 우연히 겹친 경우도 같은 경로다.
- 양팀 실행: 둘 다 후보가 있으면 함께 적용. 한쪽만 가능하면 **아무것도 바꾸지 않고** "팀 A만 적용 / 취소"를 묻는다. 둘 다 불가면 원인만 보여준다.
- 후보 없음: "팀 조정 / 이번 경기만 반복 허용 / 새 순환 시작". 새 순환 시작은 서버 요청이며 현재 주기를 닫고 새 주기를 연다. 반복 허용은 이전 사건을 지우지 않고 주기의 사용 인원 수에 더하지 않는다.
- 포지션 고정과 충돌(고정된 서포터가 이미 차례를 썼거나 후보 전원이 다른 자리에 고정): "고정 해제 / 직접 수정" 경로를 보여준다.
- 주기는 세션에 속한다. 새 세션은 새 주기로 시작한다. 주기는 자동으로 끝나지 않는다.
- 순환을 끄면 사건을 만들지 않을 뿐 기존 사건은 남는다. 다시 켤 때 활성 주기가 있으면 "이어가기 / 새 순환"을 묻는다. 꺼져 있던 동안의 경기를 소급해 사건으로 만들지 않는다.
- 지난 경기 입력과 이관 경기는 사건을 만들지 않는다.

반대: 추첨이 기기에서 일어나면 운영자가 저장소를 지우고 다시 뽑을 수 있다. → 답: 지인 모임 도구이며 운영자는 어차피 포지션을 직접 고칠 수 있다. 추첨 유지의 목적은 조작 방지가 아니라 실수로 결과가 바뀌는 일을 막는 것이다.

## P2-6. 팀 추천

- 운영자 기기에서 계산한다(126개 분할은 즉시 끝난다). 조회자에게는 그룹 정보가 전달되지 않으므로 서버 계산이 필요 없다.
- 열 명 중 첫 번째 참가자를 팀 A에 고정하고 나머지 9명에서 4명을 고르면 중복 없이 126개가 된다.
- 가중치(미확인·가정, 모임 설정값): 그룹 1~4에 4·3·2·1. 미지정은 순위 없이 **지정된 참가자 가중치의 중앙값**을 쓰고, 미지정 인원 수를 별도 기준으로 양팀에 나눈다.
- 비교 순서(미확인·가정, 사전식 비교이므로 뒤 기준이 앞 기준을 뒤집지 않는다):
  1. 같은 팀·다른 팀 조건 충족(불충족 분할은 제외)
  2. 가중치 합의 차
  3. 최상위 그룹 인원 차
  4. 최하위 그룹 인원 차
  5. 미지정 인원 차
  6. 시드로 정한 순서(재현 가능)
- 표시: 첫 후보는 "기본 추천"과 한 줄 이유("그룹 합계가 같고 최상위 인원이 2:2입니다"). 다른 후보와 상세는 펼침. 후보가 3개 미만이면 있는 만큼만. 점수는 "합계 차 1"처럼 표시하고 확률·퍼센트로 쓰지 않는다.
- 미리보기는 초안을 바꾸지 않는다. 적용 시 손으로 고친 초안이면 확인하고, 직전 편성 1단계를 기기에 보관해 되돌린다.
- 조건이 모순이면 어떤 조건끼리 충돌하는지와 해제 버튼을 보여준다.
- v1 추천은 라인 성적을 쓰지 않는다. 포지션이 무작위이므로 라인 성적 기반 추천은 실제 배정과 어긋나기 때문이다.
- 후속 연결 지점: 기준 6을 "최근 함께한 횟수가 적은 순"으로 바꿀 수 있게 비교 함수 목록으로 구성하고, 시드를 초안에 남긴다.

반대: 미지정을 중앙값으로 두면 신규 고수가 한 팀에 몰릴 수 있다. → 답: 기준 5가 미지정 인원을 양팀에 나눈다. 그래도 어긋나면 운영자가 그룹을 지정하면 된다.

## P2-7. 결과 입력·정정

- 창 하나에서 세 단계: ① 명단(이름·포지션)을 보며 승리 팀 선택 → ② "승리한 팀은 어느 진영이었나요?" 블루 / 레드 / 기억나지 않음 → ③ 요약 확인 후 저장.
- 진영은 미리 선택돼 있지 않다. 승리 팀을 바꾸면 ②의 선택을 비운다.
- 서버는 (승리 팀, 승리 팀의 진영)을 받아 "팀 A의 진영"으로 바꿔 저장한다. 미상이면 개인 승패는 집계되고 진영 통계에서만 빠진다.
- 서버 확인 전 문구는 "저장 중", 확인 뒤 같은 자리에 "3경기 저장됨 · 팀 B 승 · 레드"와 함께 기록 보기 / 수정 / 다음 경기 준비를 보여준다.
- 정정은 항목별 요청이다.

| 정정 항목 | 바뀌는 것 | 바뀌지 않는 것 | 사전 안내 예 |
|---|---|---|---|
| 승리 팀 | 10명의 승패, 진영별 성적 | 명단, 순환 | "10명의 승패가 서로 바뀝니다. 진영을 다시 확인해 주세요." |
| 진영 | 진영 통계 | 개인 승패 | "진영만 변경합니다. 개인 승패는 유지됩니다." |
| 포지션 | 라인별 통계 | 승패 | "라인별 기록이 다시 계산됩니다." |
| 경기 시각 | 오늘·시즌 필터 소속 | 세션, 승패 | "이 경기가 다른 시즌으로 옮겨질 수 있습니다." |
| 참가자 교체 | 두 사람의 전적·배치 판수 | 나머지 8명 | "○○의 기록에서 빠지고 △△의 기록에 추가됩니다." |

- 정정은 추천·배정·추첨을 다시 실행하지 않는다. 경기 ID는 유지되고 이력이 한 줄 늘어난다.
- 포지션·참가자 정정으로 그 경기의 서포터가 달라지면 "서포터 차례 기록도 함께 고칠까요?"를 묻는다(기본: 함께 고친다). 주기가 이미 끝났으면 기록만 바뀌고 현재 차례에는 영향이 없음을 알린다.
- 개인 통계의 참여 경기 목록에서 경기 상세로, 운영자는 거기서 정정으로 이어진다. 조회자는 경기 링크를 복사해 운영자에게 보낼 수 있다. 제보 접수 기능은 없다.

반대: 참가자 교체 정정은 배치 판수를 바꿔 칭호가 사라질 수 있다. → 답: 사전 안내에 "△△는 배치 10/10이 됩니다, ○○는 9/10이 됩니다"처럼 결과를 계산해 보여준다.

## P2-8. 저장 상태·실패 처리

| 상태 | 뜻 | 문구 | 다음 행동 |
|---|---|---|---|
| 서버 확인 | 서버 응답을 받음 | "저장됨 · 시각" | — |
| 캐시 | 이전에 받은 내용을 보여주는 중 | "○분 전 내용" | 새로 고침 |

| 결과 확인 불가 | 보냈으나 응답이 없거나 해석할 수 없음 | "저장됐는지 확인하지 못했어요" | "확인하기"(요청 ID 조회) |

- 재조회는 읽기만 한다. 실패한 변경을 다시 보내지 않는다.
- 명단 공유·복사 실패는 경기 저장에 영향이 없다.

## P2-9. 권한과 링크

| 동작 | 운영자 | 조회 토큰 | 없음 |
|---|---|---|---|
| 현재 경기·확정 기록·통계 조회 | 가능 | 가능 | 불가 |
| 실력 그룹·추천 근거 조회 | 가능 | 공개 정책에 따름 | 불가 |
| 수정 제안 | — | v1 없음(링크 공유로 대체) | 불가 |
| 시작·결과 확정·정정 | 가능 | 불가 | 불가 |
| 설정·참가자 관리 | 가능 | 불가 | 불가 |
| 전적 제외·복구 | 가능 | 불가 | 불가 |
| 내보내기·토큰 재발급·운영자 교체 | 가능 | 불가 | 불가 |

- 모든 요청은 서버에서 (계정 → 모임 권한) 또는 (조회 토큰 → 모임)을 확인한다. 실패한 요청은 어떤 행도 버전도 바꾸지 않는다. 다른 모임의 ID를 넣은 요청은 존재 여부를 드러내지 않고 같은 오류를 돌려준다.
- 링크 세 가지:
  - 초대 링크: 모임 조회 주소. 추측할 수 없는 토큰을 담는다. 운영자가 재발급하면 이전 링크는 무효다.
  - 현재 경기 링크: 조회 주소 + "지금". 항상 진행 중 경기를, 없으면 가장 최근 경기를 보여준다.
  - 특정 경기 링크: 조회 주소 + 경기 번호. 그 경기가 현재 경기가 아니면 "현재 경기 보기"를 함께 보여준다.
- 참가자가 링크를 열면 모임 이름, 경기 번호, 확정 여부, 진행·종료 상태, 양팀 명단을 본다. "내 이름"을 고르면 다음부터 자기 팀·포지션이 맨 위에 나온다.
- 운영자 교체: 현재 운영자가 1회용 인수 링크(24시간)를 만들고, 받은 계정이 수락하면 권한이 옮겨 간다. 운영자가 연락되지 않는 경우는 P4-4의 수동 절차로 다룬다.
- 조회 응답은 허용 목록의 필드만 내보낸다. 이메일·그룹·가중치·요청 기록·토큰은 조회 응답·백업·로그에 넣지 않는다.
- 입력 검증: 이름 1~20자, 제어 문자 제거, 요청 본문 16KB 이하, 허용하지 않은 필드는 거절. 이름은 항상 텍스트로 출력하고 HTML로 삽입하지 않는다.

반대: 토큰 링크가 채팅방 밖으로 퍼지면 누구나 기록을 본다. → 답: 조회 범위가 이름·팀·승패뿐이고 실력 그룹은 기본 비공개다. 재발급으로 차단할 수 있다. 로그인 조회는 "가입 없는 확인"(장면 4)을 깨므로 택하지 않는다.

## P2-10. 공개 정책

| 대상 | 기본(그룹 비공개) | 그룹 공개 모임 |
|---|---|---|
| 운영자 | 개인 그룹, 합계·구성, 상세 추천 근거 | 같음 |
| 조회자 | 확정 팀·포지션, "운영자가 정한 기준으로 팀을 나눴어요" | 개인 그룹과 추천 근거 중 운영자가 고른 범위 |

- 비공개에서는 합계·그룹 구성도 내보내지 않는다. 합계와 인원 구성으로 개인 그룹을 역산할 수 있기 때문이다.
- 조회 응답, 캐시, 명단 텍스트, 조회자용 내보내기는 **같은 직렬화 함수**를 거친다. 운영자 백업만 그룹을 포함한다.
- 공개 설정을 바꾸기 전에 "조회자에게 이렇게 보입니다" 미리보기를 보여준다.
- 공개 여부는 추천 계산에 쓰이지 않는다.

반대: 비공개가 기본이면 참가자가 팀 편성을 불신할 수 있다. → 답: 평가가 드러나 생기는 갈등이 더 되돌리기 어렵다. 공개는 한 번의 설정으로 켤 수 있고 반대 방향은 이미 본 사람에게 소용이 없다.

## P2-11. 통계·배치·칭호·정렬 규칙

통계는 저장하지 않고 **유효 확정 경기**(상태가 결과 확정인 경기)에서 매번 계산한다. 규모 가정상 모임당 연 수백 경기다.

**배치·칭호**
- 배치 판수 = 모임 전체 누적 유효 확정 경기 수. 0~9 진행 중, 10 이상 완료. 제외·복구·정정 때마다 다시 센다. 대기·취소·제외 경기는 세지 않는다.
- 표시: "배치 진행 중 · 7/10경기 · 4승 3패". 배치 중을 낮은 실력처럼 표시하지 않는다.
- 칭호: 배치 완료자에게 누적 승률 구간별로 붙고 "누적 기준" 라벨을 단다. 시즌 필터로 바뀌지 않는다.
- 칭호 구간·이름은 미확인이다. 모임 설정값으로 두고 기본값을 승률 65% 이상 / 55~65 / 45~55 / 35~45 / 35 미만의 5구간으로 제안한다(미확인·가정). 이름은 기존 자료 확인 뒤 채운다.

**필터**

| 항목 | 전체·시즌·오늘 필터 적용 |
|---|---|
| 경기 수·승·패·승률, 라인별, 진영별, 시너지, 상대 전적, 연승·연패, 그래프 | 적용 |
| 최근 10·20 | 선택 범위 안에서 계산. 실제 집계 수 표시("최근 7경기") |
| 시즌 랭킹 | 시즌 성적으로 순위. 배치 여부는 누적 기준. 시즌 최소 경기 기준 없음 |
| 배치 판수, 칭호 | 적용 안 함. "누적 기준" 라벨 |

- 자료가 없는 라인·진영·연도는 "기록 없음"이다. 진영별 통계에는 "진영 미상 3경기 제외"처럼 제외 수와 이유를 붙인다.
- 오늘의 결과: 가장 최근 세션의 확정 경기 목록, 경기별 결과, 개인별 성적, 결과 미입력 경기. 팀 A·B의 승수를 합산하지 않는다(매 경기 구성이 다르다). 고정 팀 시리즈는 후속이다.

**개인 통계 순서**: 요약 → 최근 → 라인별 → 시너지 → 상대 전적 → 참여 경기(맨 아래).

**정렬**

| 화면 | 기본 정렬 | 배치 완료자 우선 |
|---|---|---|
| 소환사 랭킹, 승률 그래프, 플레이어×라인, 검색어 없는 목록 | 승률 | 적용 |
| 이름 검색 결과 | 일치도 | 미적용. 배치 상태는 따로 표시 |
| 참가자 선택 | 최근 참가 순, 검색 일치 | 미적용 |
| 시너지·상대 전적 | 함께한 경기 수. 승률순 선택 가능 | 미적용 |

- 동률: 승률 → 경기 수 많은 순 → 이름 → 참가자 ID.
- 조회 범위에 경기가 없는 사람은 순위에 넣지 않는다.
- 시너지·상대 전적은 승률 옆에 경기 수를 항상 쓰고, 5경기 미만은 "자료 적음"으로 표시하며 관련 경기 목록으로 연결한다. "○○와 하면 진다" 같은 문장은 만들지 않고 수치만 보여준다.
- 새 순환 시작은 전적을 바꾸지 않는다. 추천 미리보기와 초안은 전적을 만들지 않는다.

반대: 매번 계산하면 느려질 수 있다. → 답: 모임당 수천 경기까지는 한 번의 조회로 끝난다. 느려지는 시점이 측정되면 집계 캐시를 추가하며, 원본이 정확하므로 언제든 다시 만들 수 있다.

## 세 관점의 절충

- 사용자 대 개발자: 초안을 기기에만 둔다. **선택: 서버 상태와 충돌 규약 축소. 포기: 기기 간 초안 이어 쓰기.**
- 사용자 대 개발자: 삭제를 전적 제외 하나로 합친다. **선택: 복구 가능성과 상태 수 감소. 포기: "완전히 지우기".**
- 사업 대 사용자: 조회는 토큰 링크로 가입 없이 연다. **선택: 참가자 진입 장벽 제거. 포기: 누가 봤는지에 대한 통제.**
