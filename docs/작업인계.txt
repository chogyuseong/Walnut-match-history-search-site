1. 다른 컴퓨터에서 시작하는 방법
==================================================

저장소: https://github.com/chogyuseong/Walnut-match-history-search-site.git
브랜치: design-kit  (main 이 아니다. main 은 1차본에 머물러 있다)
이 자료를 쓴 시점의 마지막 커밋: 41a8fa9 "수정" — 원격(origin/design-kit)에 올라가 있음

  git clone https://github.com/chogyuseong/Walnut-match-history-search-site.git
  cd Walnut-match-history-search-site
  git checkout design-kit
  npm install

필요한 것: Node.js 24 이상(이 PC는 v26.13.0), npm.
e2e 를 돌리려면 한 번:  npx playwright install chromium

git 에 들어 있지 않아서 새 컴퓨터에서 직접 만들어야 하는 것
  - .dev.vars  (프로젝트 폴더 맨 위, 로컬 전용 비밀값. 한 줄)
        SESSION_SECRET=아무_문자열_32자_이상
    운영 값이 아니므로 새로 아무 값이나 지어 넣으면 된다.
  - 로컬 DB(.wrangler 폴더)는 따라오지 않는다. 새 컴퓨터는 빈 DB 로 시작한다.
    합성 데이터가 필요하면 서버를 띄운 뒤 다른 창에서  npm run seed
  - 이 파일(docs/작업인계.txt)은 작성 시점에 아직 커밋되지 않았다.
    커밋·푸시하거나 파일을 직접 옮겨야 다른 컴퓨터에서 보인다.

자주 쓰는 명령
  npm run dev        화면 빌드 → 로컬 DB 마이그레이션 → http://127.0.0.1:8787
  npm run typecheck  타입 검사
  npm test           단위·통합 테스트 (작성 시점 411개 통과)
  npm run e2e        브라우저 흐름 테스트 (작성 시점 70개 통과)
  npm run seed       떠 있는 로컬 서버에 합성 데이터(30명, 120경기) 넣기

로컬에서 로그인하는 방법
  - 화면 오른쪽 위 [로그인] → [회원가입] 으로 아이디·비밀번호 계정을 만든다. 또는
  - 로그인 창 아래 점선 상자의 "개발용 로그인"(로컬 서버에서만 보임).
    npm run seed 로 넣은 합성 데이터는 개발용 로그인 계정 이름 seed 에 들어 있다.
  - "모임" 탭은 로그인해야 보인다.

2. Claude 에게 일을 시키는 방식 (사용자가 정한 규칙)
==================================================

이 PC 의 C:\Users\<사용자>\.claude\CLAUDE.md 에 있는 개인 설정이다.
다른 컴퓨터에는 자동으로 따라가지 않으니, 같은 방식으로 일하려면 그 컴퓨터에도 넣어야 한다.

  - 메인(Claude)은 팀 리더로 일한다. 작업을 시작하기 전에 실행 계획부터 보여준다.
  - 메인은 대화, 계획 수립, 결과 검토를 맡는다.
  - 새 기능 구현, 여러 파일에 걸친 수정, 버그 수정은 hard-worker 에게 위임한다.
  - 한두 줄짜리 수정, 파일 읽기, 명령 실행은 메인이 직접 한다.
  - 새 프로젝트나 큰 구조 변경의 설계는 요청할 때만 fable-designer 에게 맡긴다.
  - 모든 응답은 한국어로 한다.

에이전트 정의 파일(C:\Users\<사용자>\.claude\agents\)과 모델
  - fable-designer : Fable (설계, 요청할 때만)
  - hard-worker    : Opus  (구현 전반)
  - deep-reasoner  : Opus  (어려운 판단, 코드 검토)
  - fast-worker    : Sonnet (단순 실행)
이 파일들도 다른 컴퓨터에는 직접 옮겨야 한다.

이번 세션에서 사용자가 추가로 말한 것
  - "기능들 모두 완벽히 구현하기 전까지 끝내지 마. 지금 너무 허술해."
  - 작업 중인지 아닌지 알 수 있게 해 달라 → 답을 마칠 때 실행 중인 작업이 있는지 적기로 함.

3. 대화 흐름 (시간 순서)
==================================================

(1) 디자인 키트 적용 검증
  요청: docs/구현현황.md 를 읽고 "디자인 키트 적용" 검증부터 이어서.
  한 일: 멈춰 있던 dev 서버를 끄고 e2e 13개 통과 확인. 테마 3종 화면의 글자 명도 대비를 재서
        라이트 테마의 금색 순위 숫자, 승률 초록, 그래프 표 진한 칸의 경기 수 글자를 고침.

(2) "기능 아직 다 안 만든 거지? 전적 검색이 없네"
  확인: 전적 검색은 홈 아래와 기록 탭 안에 있었지만 메뉴가 없어 눈에 안 띄었다.
  이어서 "다 만들어 진행해", "빠진 전적 사이트 기능들 다 구현해", "완벽히 구현하기 전까지 끝내지 마".

(3) 기능 채우기 — hard-worker 여러 명이 나눠 만들고 메인이 통합 검증
  전적: 검색 메뉴, 경기 카드(양 팀 10명), 홈 요약, 랭킹 정렬·라인별·연승·최근 승패,
        개인 통계 요약과 승률 추이, 기록 거르기, 두 사람 비교, 칭호, 연도별 보기
  운영: 좌우 바꾸기, 지난 경기 한 건 입력, 참가자 고르기 격자, 결과 이미지(PNG),
        중복 참가자 합치기(되돌리기 포함), 팀 추천 조합 다양성
  서버: 카카오·Google 로그인, 요청 수 제한, 백업 복원, 모임 삭제·탈퇴,
        개인정보 처리방침 화면(초안), docs/배포안내.md
  미뤄 뒀던 검증 시나리오(7, 13, 19, 21, 29, 30, 39번)의 화면 테스트 추가

(4) "구글 시트에서 전적 가져오는 기능도 넣어 봐"
  시트 링크 → 열 맞추기 → 확인 → 가져오기. 다시 가져오면 새 줄만 들어간다.
  붙여넣기 입력과 중복 판별(지문)을 통일. 미래 날짜 경기는 거절.

(5) 독립 코드 검토 (deep-reasoner, 읽기 전용)
  치명·높음 등급 결함 없음. 중간 2건, 낮음 11건.
  고친 것: 일괄 입력 묶음 복구로 같은 경기가 두 번 집계되던 문제, 큰 복원이 동시에 돌 때의 잠금,
          가짜 로그인이 운영에서 열릴 수 있는 조건, 다른 사이트에서 보낸 요청 방어(Origin 확인),
          복원 파일 검증, 로그에 남던 토큰, 시트 리디렉션 허용 범위 등.
  배포 안내에 주의 사항으로만 적은 것: workers.dev 주소와 맞춤 도메인을 같이 열면 한쪽 로그인이 실패.
  검토가 보지 못한 영역: 1차본의 경기 흐름(시작·결과·정정), 화면 파일 대부분. 테스트로만 확인됨.

(6) "모임 탭이 없는데?"
  원인: 모임 탭은 로그인해야 보이는데 로그인 진입점이 홈 아래 작은 링크뿐이었다.
  고침: 상단 바에 [로그인] 버튼과 로그인 상태 표시. 로그인이 필요한 주소로 바로 들어오면 안내 뒤 그 화면이 열림.
       모임이 없는 계정도 모임 탭에서 시트·붙여넣기·백업·기존 사이트 기록으로 바로 시작 가능.

(7) "로그인을 하기 위해서 회원가입을 만들어 놔야지, 최소한의 조건만 걸어서"
  만든 것: 아이디 + 비밀번호 회원가입(자체 계정).
    아이디   3~20자, 영문 소문자·숫자·밑줄
    비밀번호 8자 이상, 아이디와 다르게. 조합 규칙 없음
    이메일·전화번호는 받지 않는다
    가입 직후 복구 코드를 한 번 보여 준다. 비밀번호를 잊으면 그 코드로만 다시 정할 수 있다
  카카오·Google 키가 없어도 이 계정만으로 운영할 수 있다.

(8) "지금 시트 주소 넣으면 이상하게 떠. 내가 알기론 apps 를 이용해야 될 텐데"
  조사: 저장소 첫 커밋(e4e1919)에 기존 사이트(v1, 천안호두.GG) 코드가 남아 있었다.
    - 기존 사이트는 Apps Script 웹 앱 주소(script.google.com/macros/s/…/exec)에서 기록을 받는다.
      주소는  git show e4e1919:config.js  에 있다.
    - 그 주소에 읽기 요청을 보내니 지금도 응답한다: 522경기, 26명, 전 경기 라인 정보 있음,
      블루 승 288 · 레드 승 234.
    - 시트 원본 탭 "RAW DATA기입"은 경기가 옆으로 늘어선 가로 표(28줄 × 약 1,046열)라서
      세로 표를 가정한 가져오기 화면에서 이상하게 보였다.
  만든 것:
    - "기존 사이트 기록 가져오기"(모임 탭 → 기록 관리). 연결 주소를 넣으면 기록을 그대로 받는다.
      진영(미상 / 블루·레드 그대로)과 날짜 기준(이 날짜부터의 경기를 한 해 앞으로)을 고른다.
    - 가로로 긴 시트를 네 번째 표 모양으로 지원. 탭을 이름으로 고를 수 있다.
  대조(작업자 보고): 실제 주소로 522경기를 화면으로 넣어 26명 전원의 승·패·경기 수·라인별 경기 수
    불일치 0, 다시 가져오면 0건 추가. 기존 사이트에는 읽기 요청만 보냈다.

5. 지금 멈춰 있는 지점 — 답이 필요한 질문
==================================================

질문: 내전 기록을 시작한 때가 2024년 5월인가, 2025년 5월인가?

왜 묻는가
  시트에는 날짜에 연도가 거의 없고, 기존 사이트가 연도를 추정해 저장했다.
  실제 시트의 열 순서는 다음과 같다.

    순서 1   5월 1일 ~ 12월 25일
    순서 2   1월 1일 ~ 7월 6일 (107경기)
    순서 3   12월 15일, 12월 22일, "25년 12월 28일"   ← 연도가 적힌 칸은 이것 하나
    순서 4   1월 11일 ~ 9월 20일

  시트가 시간 순서대로 적혔다면: 순서 3 은 2025년 12월, 순서 4 는 2026년,
  순서 2 는 2025년, 순서 1 은 2024년이 된다.
  기존 사이트는 순서 1 을 2026년 5~12월로 저장해 두었다(그래서 37경기가 미래 날짜가 됐다).

답에 따라 달라지는 것
  - 기존 사이트 주소 경로는 날짜가 이미 섞여 저장돼 있어서, 기준 날짜 하나로는 순서 1 의 경기를
    진짜 2026년 경기와 가려낼 수 없다.
  - 시트의 열 순서를 아는 "가로 시트" 경로로 넣어야 연도를 바로잡을 수 있다.
    시작 연도가 정해지면 그 경로로 연도를 맞춰 넣는 것을 확인해야 한다(아직 안 함).
  - 연도는 시즌·연도별 보기·최근 흐름·승률 추이에 영향을 준다. 전체 승패와 랭킹은 같다.

아직 실제로 넣지 않았다: 사용자의 로컬 DB(8787)에는 522경기를 넣지 않았다.
대조는 작업자가 따로 띄운 격리 서버에서 했다.

    CPU 한도 10ms 에 걸릴 수 있다. 걸리면 PASSWORD_PBKDF2_ITERATIONS 를 낮추거나 유료 요금제를 쓴다
  - 실제 휴대폰, iOS Safari, 실제 화면 키보드(키보드·확대는 흉내 낸 테스트)
  - 화면 스크린샷은 일부만 메인이 직접 봤다. 나머지는 자동 점검(대비·넘침·터치 크기) 결과에 의존

알려진 한계
  - 비공개 구글 시트는 읽지 못한다(공유를 "링크가 있는 모든 사용자 보기"로 해야 한다)
  - 복구 코드를 잃고 비밀번호도 잊으면 계정을 되찾을 수 없다(이메일을 받지 않기 때문)
  - 로그아웃하면 그 계정의 모든 기기에서 로그아웃된다
  - 넣은 뒤 이름을 바꿨거나 합쳤거나 라인을 고친 예전 경기는 다시 가져올 때 중복으로 안 잡힐 수 있다
  - 참가자 개인이 자기 기록만 지우는 기능은 없다

만들지 않은 것
  - 챔피언·KDA·CS 통계, Riot 계정 전적 조회(기록 자체가 없다)
  - 내전 라운지, 참가자 계정 연결, 고정 팀 시리즈, 실시간 갱신
