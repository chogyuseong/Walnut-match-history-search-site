# P3. 핵심 화면과 모바일 흐름 — 내전 운영 서비스 v2

작성일: 2026-11-05 · 선행: P0, P1, P2 문서

## 0. 입력과 표기

- [사실] P2 결정 요청에 "다음"으로 답해 기본값이 채택됐다: 순환 해법 ③, 동시 제한(세션 1·진행 중 1·대기 10·초안 기기당 1), 그룹 비공개, 초안 기기 보관, 삭제=전적 제외, 추천·칭호 가정값, 세션 경계 12시간.
- 이 문서의 화면 서술은 모두 **[제안]**이다. 시안 제작, 기기 확인, 사용자 관찰은 미수행이다.
- 와이어프레임은 390px 너비 기준 텍스트 배치다. `[ ]`는 버튼, `( )`는 선택지, `▸`는 펼침이다.

## 1. 첫 이용 흐름과 로그인 시점

이름 10개 입력 → 팀 구성 → (필요 시) 서포터 추첨 → **이 팀으로 시작** → 실제 경기 → 승리 팀·진영 확인 → 결과 저장 → 기록 확인.

로그인 위치 해법 비교:
1. 문구: 첫 화면에서 로그인을 요구하되 이유를 설명한다 → 장면 1의 멈춤 지점이 그대로 남는다.
2. 통합: 초안이 기기에만 있으므로(P2) 이름 입력·팀 구성·추첨·명단 텍스트 복사는 로그인 없이 된다. **첫 "이 팀으로 시작"에서 로그인**하고 모임은 기본 이름으로 자동 생성한다. ← 선택
3. 새 기능: 로그인 없는 임시 모임을 서버에 만들고 나중에 계정에 귀속 → 소유자 없는 데이터와 귀속 절차가 생긴다.

반대: 10명이 기다리는 순간에 로그인이 끼어든다. → 답: 그 시점에는 팀과 포지션이 이미 화면에 있고 명단 텍스트를 먼저 복사해 보낼 수 있어 경기 시작은 막히지 않는다. 로그인 왕복 시간은 인증 수단에 달려 있으므로 P4에서 한 번 누르면 끝나는 수단을 우선 검토한다.

첫 경기에 필요하지 않은 것: 실력 그룹, 시즌, 모임 이름, 참가자 계정, 공개 설정. 모두 설정 화면에 있고 비어 있어도 흐름이 막히지 않는다.

## 2. 화면 구성

하단 탭 3개: **오늘 · 기록 · 모임**. 조회자에게는 "모임" 탭과 운영자 버튼이 보이지 않는다(권한은 서버가 검사한다).

| # | 화면 | 주요 행동 (1개) | 보조 행동 |
|---|---|---|---|
| 1 | 오늘(홈) | 상태에 따라 하나: 참가자 고르기 / 현재 경기 보기 / 이어서 편성 | 결과 미입력 경기 열기, 오늘 내전 마치기 |
| 2 | 참가자 선택 | 팀 짜기 (10/10) | 지난 참가자 불러오기, 이름 붙여넣기, 검색 |
| 3 | 다음 경기 준비 | 이 팀으로 시작 | 팀 추천, 포지션 다시 뽑기, 서포터 추첨, 조건, 명단 텍스트 복사, 직전 편성으로 |
| 4 | 진행 중 경기 | 결과 입력 | 명단 공유, 다음 경기 준비, 결과는 나중에, (더보기) 미진행 취소 |
| 5 | 결과 입력 창 | 저장 | 이전 단계, 닫기(선택 유지) |
| 6 | 기록·경기 상세 | 범위 선택(오늘·시즌·전체) | 경기 열기, 사람 열기, 변경 내역, 정정(운영자) |
| 7 | 조회 화면(링크) | 내 이름 고르기 | 새로 고침, 현재 경기 보기, 기록 보기 |

### 화면 1 — 오늘(홈)

```
천안호두 내전                     저장됨 · 오후 9:12
────────────────────────────────
[상태 카드: 아래 넷 중 해당하는 것만]

(처음) 아직 경기가 없어요.
       [ 이름 넣고 팀 짜기 ]

(진행 중) 3경기 진행 중 · 오후 9:05 시작
          [ 현재 경기 보기 ]

(초안 있음) 작성하던 편성이 있어요 · 이 기기에만 있어요
            [ 이어서 편성 ]   버리기

(쉬는 중) 오늘 2경기 확정
          [ 참가자 고르기 ]
────────────────────────────────
결과 미입력 1경기                    ▸ 2경기 · 오후 8:20
오늘의 결과                          ▸ 2경기 확정
────────────────────────────────
 오늘        기록        모임
```

- 상태 카드는 한 번에 하나의 주요 버튼만 낸다. 우선순위: 진행 중 > 초안 있음 > 처음/쉬는 중.
- 예시 데이터를 채워 보여주지 않는다. 빈 상태에는 다음 행동 버튼만 둔다.

### 화면 2 — 참가자 선택

```
← 참가자 고르기                          8/10
────────────────────────────────
[ 지난 참가자 불러오기 ]  · 11월 1일 10명
[ 이름 검색 또는 새 이름 입력          ]
  여러 명은 줄바꿈으로 붙여 넣을 수 있어요
────────────────────────────────
선택됨 8
 ✓ 김용호   ✓ 조규성   ✓ 박서연  …        (누르면 빠짐)
전체
 ✓ 김용호                    선택됨
   이민재
   최하늘
────────────────────────────────
              [ 팀 짜기 (8/10) ]  ← 10명이 되면 활성
```

- 붙여넣기: 줄바꿈·탭·쉼표로 나누고 앞뒤 공백을 지운다. 빈 줄은 버린다.
- 안내는 구체적으로 쓴다: "'김용호'가 두 번 있어요. 한 번만 넣었습니다." / "이름이 12개예요. 10명만 고를 수 있어 뒤의 2명(○○, △△)은 넣지 않았습니다." / "2명이 더 필요해요."
- 새 이름이 기존 이름과 비슷하면 "혹시 '조규성'인가요?"를 먼저 보여준다(중복 참가자 예방).
- "지난 참가자 불러오기"는 선택만 채운다. 자동으로 다음 화면으로 넘어가지 않으며 여기서 빼고 더한다.
- 인원 수 "8/10"은 스크롤해도 상단에 남는다. 검색 중에도 선택된 사람은 ✓와 "선택됨"으로 구분된다.
- 검색창에 입력 중일 때 목록이 갱신돼도 입력값·포커스·스크롤 위치는 유지된다.

### 화면 3 — 다음 경기 준비

```
← 다음 경기 준비 (4경기)         이 기기에만 있어요
────────────────────────────────
● 팀 A                      ■ 팀 B
 탑   김용호                 탑   이민재
 정글 박서연                 정글 최하늘
 미드 조규성                 미드 한지우
 원딜 정다은                 원딜 오세훈
 서폿 강민수 ◆차례 씀        서폿 윤가람
────────────────────────────────
[ 팀 추천 ] [ 포지션 다시 뽑기 ] [ 서포터 추첨 ]
▸ 조건 (같은 팀·다른 팀·포지션 고정) 1개
▸ 서포터 차례: 오늘 6명 씀, 4명 남음
   명단 텍스트 복사 · 직전 편성으로
────────────────────────────────
          [ 이 팀으로 시작 ]
```

- 이름을 누르면 그 사람을 다른 자리와 바꾸는 선택 상태가 된다(끌기 없이 두 번 누르기). 끌기는 넓은 화면의 보조 수단이다.
- 이 화면에는 결과 저장 버튼이 없다.
- "◆차례 씀"은 색이 아니라 기호와 글자로 표시한다. 이미 차례를 쓴 사람이 서포터 자리에 있으면 시작 전에 알 수 있다.
- 서포터 추첨 결과는 명단 바로 아래 같은 자리에 나온다: "팀 A: 김용호 미드→서포터, 강민수 서포터→미드, 나머지 유지 · [적용] [취소]". 한쪽만 가능하면 "팀 B는 남은 차례가 없어요 · [팀 A만 적용] [취소]".
- 팀 추천은 미리보기를 먼저 보여준다: "기본 추천 · 그룹 합계가 같고 최상위 인원이 2:2입니다 · [적용] ▸ 다른 후보 2개". 조회자 화면과 명단 텍스트에는 이 근거가 없다.
- A(다음 판 준비)로 들어오면 상단에 한 줄: "지난 경기와 같은 팀이에요. 포지션은 새로 뽑았어요 · [포지션 유지] [팀 다시 짜기]".
- 시작 확인은 **한 번**이다. 반복 서포터 경고, 진행 중 경기 처리("결과 입력 / 결과는 나중에 입력하고 시작")가 있으면 같은 창 안에 함께 묻고 창을 연달아 띄우지 않는다.

### 화면 4 — 진행 중 경기

```
3경기 진행 중                     저장됨 · 오후 9:05
────────────────────────────────
● 팀 A                      ■ 팀 B
 탑   김용호                 탑   이민재
 …                           …
────────────────────────────────
          [ 결과 입력 ]
 명단 공유      다음 경기 준비      결과는 나중에
                                        ⋯ 더보기
```

- "명단 공유"를 누르면 [링크 복사] [텍스트 복사]. 복사가 거부되면 선택할 수 있는 글 상자를 그 자리에 보여준다. 텍스트 끝에는 "오후 9:05 기준"이 붙는다.
- "다음 경기 준비"는 초안이 없으면 만들고, 있으면 "다음 초안 열기"로 바뀐다.
- "미진행 취소"는 더보기 안에 둔다.

### 화면 5 — 결과 입력 창

```
3경기 결과                                  1/3
────────────────────────────────
어느 팀이 이겼나요?
( ● 팀 A )  김용호·박서연·조규성·정다은·강민수
( ■ 팀 B )  이민재·최하늘·한지우·오세훈·윤가람
────────────────────────────────  2/3
이긴 팀 A는 어느 진영이었나요?
( 블루 )   ( 레드 )   ( 기억나지 않음 )
────────────────────────────────  3/3
3경기 · 팀 A 승 · 팀 A 블루 / 팀 B 레드
              [ 저장 ]
```

- 세 단계는 한 창에서 아래로 이어진다. 진영은 미리 선택돼 있지 않고, 승리 팀을 바꾸면 진영 선택이 비워진다.
- 요약이 곧 확인이다. "정말 저장할까요?"를 따로 묻지 않는다.
- 저장을 누르면 버튼이 "저장 중"이 되고, 서버 확인 뒤 같은 자리가 다음으로 바뀐다:

```
3경기 저장됨 · 팀 A 승 · 블루             오후 9:41 확인
[ 다음 경기 준비 ]      기록 보기 · 수정
```

- 응답을 받지 못하면 "저장됐는지 확인하지 못했어요 · [확인하기]". 선택한 값은 그대로 남는다.
- 창을 닫았다 열어도 선택이 유지된다.

### 화면 6 — 기록·경기 상세

```
기록          ( 오늘 ) ( 시즌 ▾ ) ( 전체 )
────────────────────────────────
오늘의 결과 · 3경기 확정 · 결과 미입력 1
 3경기  팀 A 승 · 블루              오후 9:41
 2경기  결과 미입력                 [결과 입력]
 1경기  팀 B 승 · 진영 미상         오후 7:58
────────────────────────────────
개인 성적 (오늘)
 김용호   2승 1패
 조규성   1승 2패 · 배치 진행 중 7/10 (누적 기준)
────────────────────────────────
▸ 랭킹   ▸ 변경 내역
```

- 표 대신 행 목록을 쓴다. 한 행은 이름과 핵심 수치 두 개, 나머지는 행을 눌러 펼친다. 가로 스크롤은 플레이어×라인 표에만 남기고, 좁은 화면에서는 사람을 고르면 라인 다섯 개가 세로로 나온다.
- 범위 선택은 목록 바로 위에 붙어 있고, 누적 기준 항목에는 "누적 기준"을 글자로 쓴다.
- 경기 상세: 명단, 결과, 진영, ▸변경 이력. 운영자에게는 항목별 [수정]이 각 항목 옆에 있다(승리 팀 옆, 진영 옆, 포지션 옆). 누르면 영향 범위 한 줄과 [변경]이 나온다. [전적 제외]는 더보기 안에 있고 제외된 경기에는 [복구]가 보인다.
- 개인 화면 순서: 요약 → 최근 → 라인별 → 시너지 → 상대 전적 → 참여 경기.

### 화면 7 — 조회 화면(링크)

```
천안호두 내전 · 3경기 · 진행 중 (확정 명단)
────────────────────────────────
내 이름을 고르면 내 자리를 먼저 보여드려요  [ 고르기 ]
   → 고른 뒤:  조규성 님 · 팀 A · 미드
────────────────────────────────
● 팀 A                      ■ 팀 B
 …                           …
────────────────────────────────
오후 9:06 확인 · [ 새로 고침 ]      기록 보기
```

- 로그인이 없다. 특정 경기 링크로 들어왔는데 그 경기가 끝났으면 상단에 "이 경기는 끝났어요 · [현재 경기 보기]"가 나온다.
- 아직 시작하지 않은 편성(초안)은 여기에 보이지 않는다.
- "내 이름"은 이 기기의 표시 설정이며 언제든 바꿀 수 있다.

## 3. 공통 규칙

**상태 유지**
- 펼친 영역, 입력값, 스크롤 위치는 화면을 떠났다 돌아와도 유지한다. 서버 갱신은 바뀐 값만 바꾸고 화면을 다시 만들지 않는다.

**설명 세 종류**
- 기본 설명: 항상 보이는 한 줄.
- 펼치는 설명: "자세히"를 눌러야 보인다(순환 규칙, 추천 기준).
- 오류 해결 안내: 오류가 났을 때만, "무엇이 일어났나 → 지금 할 일" 두 줄.

**너비별 배치**

| 너비 | 배치 |
|---|---|
| 320px | 팀 A·B를 위아래로 쌓는다. 버튼 줄은 2개 + 더보기 |
| 390px | 팀 A·B 좌우 2열(와이어프레임 기준) |
| 720·768px | 왼쪽 명단, 오른쪽 행동·조건 패널의 2단 |
| 1440px | 2단 유지, 본문 최대 폭 제한 후 가운데 정렬 |

**모바일 세부**
- 긴 이름: 한 줄로 자르고 말줄임표. 누르면 전체 이름이 보인다. 요약·확인 창에서는 줄바꿈해 전체를 보여준다.
- 화면 키보드가 열리면 하단 고정 버튼을 숨기고 같은 버튼을 입력란 아래 본문에 둔다. 고정 버튼은 기기 하단 안전 영역만큼 띄운다.
- 확인 창이 열려 있을 때 하단 고정 버튼은 가려지지 않게 창이 그 위를 덮는다. 창 안의 버튼만 누를 수 있다.
- 200% 확대에서 가로 스크롤 없이 내용이 한 열로 흐른다.
- 팀은 기호(●/■)와 글자("팀 A"), 진영은 글자("블루/레드/미상"), 상태는 글자("진행 중")로 표시하고 색은 보조다.
- 터치 대상은 44px 이상, 본문 대비 4.5:1 이상, 키보드 포커스 표시 유지. [검증 필요] 실제 수치는 구현 뒤 기기와 도구로 확인한다.

**확인 창**
- 한 행동에 확인 창은 하나다. 같은 내용을 두 번 묻지 않는다.
- 되돌릴 수 있는 행동(전적 제외, 초안 버리기 직후 되돌리기)은 확인 대신 실행 뒤 "되돌리기"를 준다.

## 4. 제거한 준비·반복 조작

| 제거한 것 | 대신 |
|---|---|
| 팀 짜기 전 가입·모임 만들기 | 첫 "이 팀으로 시작"에서 로그인, 모임 자동 생성 |
| 시트 연결·재연결 | 계정에 모임이 귀속된다 |
| 저장 경로 선택(원본 읽기·가져오기·공용 저장) | 서버 한 곳. 화면에는 "저장됨 / 이 기기에만 있어요" |
| 첫 경기 전 실력 그룹·시즌 입력 | 비워 둬도 진행. 나중에 설정 |
| 매 내전 참가자 10명 재입력 | 지난 참가자 불러오기 |
| 매 경기 참가자·팀 재구성 | 다음 경기 준비가 같은 팀으로 초안 생성 |
| 진영 사전 선택 | 결과 저장 때 한 번 |
| 날짜 직접 선택 | 세션이 경기를 묶는다 |
| "정말 저장할까요?" 창 | 요약 단계가 확인 |
| 명단을 채팅에 손으로 옮겨 적기 | 링크·텍스트 복사 |
| 틀린 결과의 삭제 후 재입력 | 항목 옆 [수정] |
| 결과를 넣어야만 다음 경기 시작 | 결과는 나중에 |

## 5. 세 관점의 절충

- 사용자 대 개발자: 끌어서 옮기기 대신 두 번 누르기를 기본으로 한다. **선택: 좁은 화면과 키보드 조작에서 같은 동작. 포기: 넓은 화면에서의 빠른 끌기(보조로만 제공).**
- 사용자 대 사업: 로그인을 시작 시점으로 미룬다. **선택: 첫날 가치 확인. 포기: 방문자 전원의 계정 확보.**
- 사용자 대 개발자: 표를 행 목록으로 바꾼다. **선택: 모바일 가독성. 포기: 한눈에 보는 전체 비교(넓은 화면에서만 표 제공).**

반대(화면 구성 전체): 탭 3개와 화면 7개는 "기능이 적은 도구"치고 많다. → 답: 운영자가 경기 중 오가는 화면은 3·4·5 셋뿐이고 1은 진입, 2는 내전당 한 번이다. 6·7은 읽기 전용이다. 관찰에서 화면 3과 4를 오가다 길을 잃으면 둘을 한 화면의 두 상태로 합치는 안을 검토한다.
