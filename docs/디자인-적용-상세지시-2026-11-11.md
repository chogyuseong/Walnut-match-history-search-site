# 새 디자인 적용: 2~6단계 상세 지시 (2026-11-11)

`docs/디자인-적용-계획-2026-11-11.md`의 단계 표를 작업자가 바로 실행할 수 있게 풀어 쓴 것이다. 0·1단계는 2026-11-11에 운영에 반영했다.
줄 번호는 1단계 전 `src/web/styles.css` 기준이라 지금은 밀려 있다. 선택자 이름으로 찾는다.
확정 시안: `docs/design-mockup/home-gold.html`과 같은 폴더의 사진.

## 공통
- 단계마다 브랜치 하나(예: `design-stage-2`), 로컬 커밋만 하고 지휘가 검토한 뒤 main에 합쳐 staging → 운영 순으로 배포한다.
- `styles.css`는 CRLF다. `sed -i` 금지. 재정의를 뒤에 덧붙이지 말고 원래 선언을 고치고, 같은 선택자의 뒤쪽 덮어쓰기와 오래된 주석을 같이 지운다.
- 단계 끝 검사: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run check:bundle`, `npm run e2e`, `npm run audit:design`(숫자가 줄었는지), 사진(`SHOTS_DIR`를 주고 `e2e/design-shots.spec.ts`, 390×844·768×1024·1440×900, 다크·라이트).
- 사진 스펙은 기존 8787 서버와 겹치지 않게 `E2E_PORT=8795` 같은 새 포트로 돌린다. 스펙이 테마를 localStorage와 data-theme으로 직접 바꾸므로 사진 속 테마 선택 상자 글자는 실제와 다르게 찍힌다(버그 아님).
- 승패·진영 색(`--ih-win-*`, `--ih-loss-*`)은 이름·값을 바꾸지 않는다. `e2e/rate-colors.spec.ts`의 rgb 단언이 손대지 않고 통과해야 한다.
- 0단계에서 잰 기존 문제: 44px 미만 컨트롤(예시 랭킹 46, 챔피언 초성·정렬 버튼 24~83, 개인·비교 1440px 102, 요약 1440px 44, 기록 4~24, 모임 설정 13, 로그인 창·결과 입력 창 각 1), 예시 챔피언 768px 가로 넘침 16px. 고르기·준비·경기 화면은 0.
- 1단계에서 정한 것: fieldset 테두리는 구분선, `.choice`·`.segmented`·i 점·계정 버튼·파일 입력·눌러지는 칸의 호버 테두리는 컨트롤 경계, `button.row`는 바탕 패널·테두리 구분선, 표·목록 안쪽 포커스 offset -2px은 스크롤 상자에 잘리지 않게 하려는 것이라 유지.

## 2단계. 척도와 공통 부품 치수 (5~6시간, 커밋 넷: 간격 → 글자·굵기 → 반경·테두리 → 부품)
전역 치환이라 전 화면이 같이 움직인다. 커밋마다 390 사진을 본다. 화면 구조(마크업)와 반응형 기준은 바꾸지 않는다.

간격(허용 밖 약 296개 값):
- `:root`에 `--space-1`~`--space-8`(4·8·12·16·24·32·48·64px)을 넣고 허용값도 토큰으로 바꾼다.
- 기본 변환: 2→4, 3→4, 5→4, 6→8, 7→8, 10→padding이면 12·gap이면 8, 14→16, 18→16, 20→24(모바일 패널 안쪽이면 16), 40→48, `0.5rem`→8, `1.2em`류는 문맥에 맞는 토큰.
- 아이콘과 짧은 라벨 사이 6px은 4로. 배지 padding `2px 8px`은 `0 8px`에 line-height로 높이를 맞춘다.
- 음수 여백 9개 제거. `.info-tip`은 `margin: 0`으로 하고 제목과 한 줄 flex(`align-items: center`)에 넣는다(제목 줄이 44px로 높아지는 것은 받아들인다). `.row-label`의 `-2px`는 0.
- `.screen`: padding 16(768 이상 24), gap 24. `.card` padding 16(768 이상 24). 제목과 설명 8, 설명과 본문 24, 섹션 사이 32.

글자:
- 0.6875→0.75, 0.8125→배지·메타는 0.75·그 밖은 0.875, 0.9375→1, 1.05·1.0625·1.125→1(섹션 제목이면 1.25), 1.375→1.25, 1.6·1.625·1.75·1.875→1.5, 2.25·2.5·3.75·5.5→2rem, SVG 글자 11px·13px→12px.
- h1 1.5rem/1.3/600, h2 1.25rem/1.4/600, h3 0.875rem/1.5/500. 앞뒤 두 군데 선언을 하나로 합친다. body line-height 1.5. letter-spacing 12건 제거.
- 굵기: 800은 전부 600. 700은 h1~h3이거나 1.25rem 이상 수치면 600, 그 밖(버튼·배지·탭·라벨·이름)은 500. `button` 기본 700은 500.
- `tabular-nums`: `.data-table .num`, `.rank`, `.stat`, 점수·MMR 수치에 빠진 곳을 채운다.

반경·테두리:
- `--ih-radius-sm/md/lg` → `--radius-badge/control/panel`(4·6·8). 리터럴 10px은 8px. pill 8곳은 4px(배지)나 6px(컨트롤). 스크롤바 4px. 막대의 2·3px은 4px. 카카오 버튼 12px은 예외.
- 2px 이상 테두리 47건: 진영·승패를 뜻하는 것은 1px 색 테두리와 기호로, 선택 표시는 `--ih-selected` 배경으로.
- inset 3px 표시선 8건 제거. `.note`의 `border-left: 3px`은 1px.

효과:
- `transition`은 `background-color`·`border-color`·`color`에 `var(--motion)`(120ms)만.
- `mmr-enter`, `viz-draw`, `viz-fade` 키프레임과 사용처 삭제. `TeamBoards.tsx`의 자리 바뀜 이동은 조작 결과를 보여 주는 것이라 둔다.
- `.tabs` 가운데 맞춤 `translateX(-50%)`는 3단계에서 없앤다.

공통 부품 치수(원래 선언을 고치고 뒤쪽 덮어쓰기를 지운다):
- `button`: min-height 44, padding `0 16px`, 반경 6, 14px/500.
- `input`·`textarea`·`select`: min-height 44, padding `8px 12px`, 16px.
- `.badge`·`.tag`: 12px/500, 반경 4. `.card`·`.team`·`.candidate`·`details`·`fieldset`: 반경 8, 테두리 1px `--ih-line`.
- `.data-table`: th 14/500, td 14/400, 행 최소 48px, 숫자 오른쪽 정렬.
- `.dialog`: 반경 `8px 8px 0 0`(768 이상 8px), padding 16(768 이상 24), gap 16. `.toast` 14/500. `.stat-card` 값 2rem/600, 제목 12px.
- 44px 미만 컨트롤(위 목록)을 여기서 고친다: 보이는 크기를 키우기 어려운 곳은 누르는 영역만 44px로 넓힌다.

걸릴 테스트: `prep-walkthrough.spec.ts`(한 줄 높이 대비 글자 크기), `login-entry.spec.ts`(상단 바와 탭 겹침), `first-use.spec.ts`(팀 상자와 시작 버튼 위치, 버튼 높이 50px 이하), `live-roster.spec.ts`(44px). 실패하면 화면이 실제로 깨졌는지 먼저 보고, 아니면 기대값만 고친다.
완료 기준: audit의 간격·글자·굵기·반경·transition 위반 0(명시 예외 제외), 390에서 넘침 0, 보이는 컨트롤 44px, 200% 확대에서 내용이 사라지지 않음.
위험: h2가 17→20px, 간격 6→8로 커져 조밀한 줄(준비 화면 명단, 랭킹 줄, 하단 탭 6칸)이 넘칠 수 있다.

## 3단계. 화면 틀과 첫 화면 (3~4시간)
범위: `App.tsx`(TopBar·Tabs·LegalFooter·뷰어 메뉴), `screens/Intro.tsx`, `Today.tsx`, `Dashboard.tsx`의 빈 안내, `styles.css` 틀 구역.
- 반응형 기준: 720→768, 719→767, 1024→1200, 1023→1199. JS도 같이(`Dashboard.tsx`의 `useMediaQuery("(min-width: 1024px)")`, 주석의 720·1024 표기). 359·399·419·479·480 기준은 하나씩 필요한지 확인.
- 폭: `main` max-width 1200, `--content-max: 1200px`, `--reading-max: 720px`. 좌우 여백 16 / 768 이상 24 / 1200 이상 32.
- 상단 바: 배경 `--ih-bg`, 아래 1px `--ih-line`, 높이 64. 로고는 사이트 이름 16px/600 중립색.
- 주 메뉴: 767 이하 하단 고정 64px, 배경 `--ih-panel`, 20px 선 아이콘(1.5px) + 12px 글자(시안의 `<symbol>` 5개, 나머지는 같은 굵기로 직접 그림). 768 이상은 겹치기를 없애고 상단 바 아래 한 줄(`nav.tabs`를 `<main>` 앞으로). `html`의 scroll-padding과 `main`의 padding-bottom을 새 높이에 맞춘다. 뷰어 메뉴도 같은 모양.
- 첫 화면(Intro): 시안 구조대로. 카드를 벗기고 소개 제목 2rem/600 + 설명 한 문단, 주 버튼 "로그인 없이 팀 짜기" 하나, 보조 "예시 기록 보기", 텍스트 링크 "로그인하고 모임 만들기", 안내 한 줄. 기능 목록은 상자 없이 1px 구분선 목록 4개(아이콘 20px + 제목 16/500 + 설명 14). 1200 이상은 왼쪽 소개, 오른쪽 기능 목록.
- 첫 방문자에게는 아래 "아직 경기가 없어요 / 이름 넣고 팀 짜기 / 전적 검색 / 기록이 쌓이면 여기에" 묶음을 숨긴다. 재방문자·로그인 사용자의 오늘 화면은 그대로.
- 상단 "로그인" 버튼과 "로그인하고 모임 만들기" 링크가 겹친다. 어느 쪽을 남길지 사용자에게 확인한다(미정).
- 설명 문장의 "라이엇 전적에 남지 않아요"는 `e2e/search-index.spec.ts`·`intro-demo.spec.ts`가 확인한다. 바꾸려면 사용자 확인 후 테스트와 함께.
- 법적 고지: 12px, `--ih-text-secondary`, 위 간격 48, 링크 최소 높이 44.
걸릴 테스트: `intro-demo.spec.ts`, `first-use.spec.ts`, `search-index.spec.ts`, `login-entry.spec.ts`. 390×844에서 주 버튼이 하단 탭 위에 다 보이는 단언은 유지.
위험: 1024~1199px 창에서 준비·대시보드·우선순위의 2단이 1단이 된다. `nav` 위치 이동으로 키보드 순서가 바뀐다.

## 4단계. 통계·조회 화면 (5~6시간)
범위: `Dashboard`, `Records`, `OperatorRecords`, `Ranking`, `Person`, `Graphs`, `graphFigures`, `Compare`, `ChampionTier`, `Search`, `SeasonSummary`, `Viewer`, `ViewerLive`, `Demo`, `matchCard`, `screenKit`(StatCard·SortHead·DataTable), `shareImage`.
- 카드 중첩 해소: 섹션은 제목 + 구분선, 반복 데이터는 표·목록. 마크업을 고친 뒤 `.card :where(.card)` 임시 규칙을 지운다. Compare·Person·Graphs부터.
- 요약 영역은 핵심 지표 최대 3개. 오늘·시즌·누적 기준을 값 옆에 적는다.
- 랭킹 1위 `.stat-card.is-lead`: 골드 채움을 없애고 일반 패널 + "1위" 라벨.
- 승률 색: 3단(55% 이상 `--ih-accent`, 45~55% 주요 글자, 45% 미만 보조 글자), 막대에 50% 기준선. `heat-h*` 클래스 이름은 남겨 테스트 변경을 줄인다. `--heat-text-0`에 옛 색(#eceef1·#1b1a17)이 남아 있다.
- 칭호 8색·MMR 티어 5색·금은동·추천 창 티어 색은 중립화(도형·이름·순번·테두리로 구분). 라인 5색(`--pos-*`)은 유지. `--viz-series`(파랑 #5690d9)는 `--ih-text-secondary`로. 범례 있는 그래프의 `--viz-cat-*`만 남긴다.
- 빗금 3곳(패 막대·비교 B·tone-muted)은 속 빈 테두리 막대로.
- 표: 숫자 오른쪽, 이름 왼쪽, 셀별 배경색 제거. 승패는 글자와 기호를 같이. 요약 표의 ●A 파랑·■B 빨강은 유지.
- 빈 기록 상태는 안내 하나와 행동 하나. 화면마다 최초 노출 영역의 주 버튼 하나(Records 7개 확인).
- `shareImage.tsx`로 내보낸 이미지가 새 색으로 그려지는지 눈으로 확인(미확인 영역).
걸릴 테스트: `rate-colors.spec.ts`(빗금 backgroundImage, "색이 서로 다르다" 단언), `theme-contrast.test.ts`(heat·grade 검사), 구조가 바뀌는 곳의 role·name.
하지 말 것: 통계 계산, 정렬 기준, 표본 기준 변경.

## 6단계. 마감 (2시간)
- `:root` 별칭 블록과 안 쓰는 옛 토큰 삭제(`--line`, `--primary`, `--warn-*`, `--ok-*` 등 남은 별칭), 덮어쓰기 층을 원래 선언으로 합치기, 구역 머리 주석의 옛 이력 정리.
- `scripts/design-audit.mjs`를 허용 밖 값이 나오면 실패하게 바꾸고 `scripts/predeploy-check.mjs`나 lint 흐름에 건다.
- `theme.ts`: violet·deeplol 저장값을 dark로 고쳐 쓴다.
- README와 `docs/구현현황.md` 갱신, 최종 사진 묶음.
- 전체 적용이 끝나면 Fable에게 결과 검토를 맡긴다(모델 사용 규칙).
