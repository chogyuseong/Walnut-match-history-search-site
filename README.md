# 내전 운영 서비스 v2 (naejeon-v2)

리그 오브 레전드 5:5 내전 모임을 위한 **팀 편성·전적 기록 사이트**입니다.
개인이 여는 사용자 설정 게임은 Riot 서버에 기록이 남지 않으므로, 운영자가 직접 입력한 승패·라인·진영으로 전적을 쌓습니다.

- 최종 갱신: 2026-11-10
- 상태: **로컬에서만 검증됨. 아직 배포하지 않았습니다.** (배포 순서: [`docs/배포안내.md`](docs/배포안내.md))
- 상세 기록: [`docs/구현현황.md`](docs/구현현황.md) · 설계 문서: `docs/P0~P4` · 서버 개선 기록: `docs/개선-서버-*.md`

---

## 1. 한눈에 보기

| 역할 | 하는 일 | 들어오는 길 |
|---|---|---|
| 운영자(대표) | 참가자 고르기 → 팀 편성 → 경기 시작·결과 입력, 전적·설정 관리 | 로그인(자체 계정·카카오·Google) |
| 공동 운영자 | 운영자와 같되 모임 삭제·복원 등 대표 전용 작업 제외(최대 5명) | 1회용 초대 링크 |
| 참가자(본인 연결) | 내 전적·내 기피 라인, 본인 확인 참가 신청, 정정·삭제 요청 | 운영자가 보낸 연결 링크 + 로그인 |
| 조회자 | 명단·기록·랭킹·개인 통계·시즌 요약 읽기 | 조회 링크(로그인 없음) |

핵심 흐름: **참가자 고르기(10명 + 대기자) → 준비 화면(티어·기피 라인·서포터 횟수를 반영해 섞기, 손으로 고치기) → 이 팀으로 시작 → 결과 입력 → 전적·랭킹·MMR·칭호 자동 반영**.

화면 지도(상단 탭 기준):

| 탭 | 보는 것 | 주소 |
|---|---|---|
| 오늘 | 오늘의 결과, 진행 중 경기, 다음 경기 준비로 가는 버튼 | `#/` |
| 검색 | 이름(초성 가능)·날짜·메모로 사람과 경기 찾기 | `#/search` |
| 기록 | 경기 카드와 거르기, 소환사 랭킹(승률·경기 수·승수·MMR 순), 시즌 요약, 개인 통계·두 사람 비교로 이어짐 | `#/records`, `#/p/ID`, `#/compare` |
| 랭킹 | MMR 순위표 전용. 누적 기준, 묶음 세 개(누적 50경기 이상 → 배치 완료 → 배치 진행 중), 행을 펼치면 MMR 추이 | `#/ranking` |
| 분석 | 그래프 분석: 섞기 공정성, 이야기 띠, 보기 6종, 플레이어를 고르면 그 사람 중심 묶음 | `#/graphs`, `#/graphs/ID` |
| 모임 | 운영자 설정: 참가자·티어·기피 라인·시즌·배치 경기 수·칭호·가져오기·백업·공동 운영자 | `#/group` |

조회 링크(`#/v/토큰/...`)와 예시 모임(`#/demo/...`)도 요약·검색·기록·랭킹 메뉴를 같은 화면으로 봅니다.

## 2. 개발 환경

### 기술 스택

| 영역 | 사용 기술 | 비고 |
|---|---|---|
| 서버 | Cloudflare Workers + [Hono](https://hono.dev) 4, D1(SQLite), R2(자동 백업), Cron Trigger | 무료 요금제 기준으로 설계(요청당 CPU 10ms, D1 하루 쓰기 10만 행) |
| 화면 | React 19 + Vite 8, TypeScript 7 | UI 라이브러리 없음. 디자인 토큰(CSS 변수) + 직접 만든 부품, 테마 3종(다크·바이올렛·라이트) |
| 공용 로직 | `src/shared` 순수 함수 | 서버와 화면이 같은 계산(통계·편성·칭호·MMR)을 씀 |
| 테스트 | Vitest 5(단위·통합, Workers 런타임), Playwright(브라우저 흐름) | 2026-11-10 기준 vitest 998개, e2e 111개 |
| 검사 | ESLint(typescript-eslint + react-hooks), `check:bundle`(JS 크기 상한) | GitHub Actions `.github/workflows/ci.yml` |
| 배포 | wrangler 4, 환경 `staging` / `production` | 운영 배포는 아직 없음 |

### 요구 사항

- Node 22.12 이상의 22, 24, 또는 26 이상(`package.json` `engines`, vitest 5와 같음. 26에서 확인), npm 11 이상
- Cloudflare 계정은 **배포할 때만** 필요합니다. 로컬 개발은 계정 없이 됩니다(wrangler가 D1·R2를 로컬에서 흉내 냄).
- 브라우저 테스트는 `npx playwright install chromium`(사파리 엔진 비교는 `webkit`)이 한 번 필요합니다.

### 처음 받았을 때

```bash
npm install
node -e "console.log('SESSION_SECRET=' + require('crypto').randomBytes(48).toString('base64url'))" > .dev.vars
npm run dev          # 화면 빌드 → 로컬 D1 마이그레이션 → http://127.0.0.1:8787
npm run seed         # (선택) 다른 창에서: 가짜 이름 30명·경기 120개 넣기
```

- `.dev.vars`의 `SESSION_SECRET`은 로컬 전용 값입니다(32자 이상, git 제외). 로컬 로그인은 개발용 가짜 로그인이라(`AUTH_MODE=fake`) 아무 이름으로 들어갈 수 있고, `e2e-site-admin`은 사이트 운영자(#/admin)입니다.
- 로컬 DB(`.wrangler/`)·빌드 결과(`dist/`)·비밀값은 git에 올라가지 않습니다. 새 PC에서는 데이터가 비어 있으니 `npm run seed`나 "백업에서 복원"을 씁니다.
- 화면 코드를 고친 뒤에는 `npm run build`를 다시 해야 `wrangler dev`가 새 화면을 줍니다(`npm run dev`가 둘을 함께 합니다).

### 명령

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 화면 빌드 → 로컬 D1 마이그레이션 → 로컬 서버 `http://127.0.0.1:8787` |
| `npm run dev:web` | Vite 개발 서버(화면만 즉시 반영, `/api`는 8787로 프록시하므로 `npm run dev`를 함께 띄움) |
| `npm run typecheck` | 서버·화면 타입 검사 |
| `npm run lint` | ESLint(권장 규칙 + React 훅 규칙. 서식은 보지 않음) |
| `npm test` / `npx vitest run` | 단위·통합 테스트(기본 제한 30초) |
| `npm run build` → `npm run check:bundle` | 화면 빌드 → 화면별 JS 크기 출력·상한 검사(가장 큰 JS 250KB, 첫 화면 330KB, 화면 조각을 못 찾으면 실패), CSS 합계 출력 |
| `npm run e2e` | 브라우저 흐름 테스트. 떠 있는 8787 서버를 그대로 씀. 다른 포트는 `E2E_PORT` |
| `npm run seed` | 떠 있는 로컬 서버에 합성 데이터 넣기(로컬 주소만 허용) |
| `npm run db:migrate:local` | 로컬 D1 마이그레이션만 |
| `npx vitest run --config vitest.measure.config.ts --silent=false` | 스냅숏 크기·통계 계산 시간 측정(경기 500·2000·5000개) |
| `npm run deploy:staging` / `npm run deploy:production` | 배포 전 점검(`scripts/predeploy-check.mjs`: 자리 표시값, production은 `legal.ts`의 `[채워야 함]`) → 화면 빌드 → `wrangler deploy --env …`. 순서·준비는 `docs/배포안내.md` 8절 |

### 폴더 구조

```
src/server/   Workers API(Hono). index.ts 라우팅, mutation.ts(모임 안 쓰기 공통 경로), snapshot.ts, auth.ts, matches.ts, groups.ts …
src/shared/   서버·화면 공용 순수 로직. stats(통계) · draft/prepTools/rotation/priority/avoid(편성) · titles(칭호) · rating(MMR) · search · seasonAwards …
src/web/      React 화면. App.tsx 라우팅, useApp.ts 상태, lazyScreens.ts 지연 로딩, screens/*(화면), screens/prep/*(준비 화면 조각), styles.css(토큰·스타일)
migrations/   D1 마이그레이션 0001~0025(0004는 없음, 번호 건너뜀)
test/         Vitest · e2e/  Playwright · docs/  설계·현황·배포 문서 · scripts/  seed, check-bundle
```

### 검사와 CI

- 로컬에서 바꾼 뒤: `npm run typecheck && npm run lint && npx vitest run && npm run build && npm run check:bundle`, 화면을 바꿨으면 관련 `e2e/*.spec.ts`.
- GitHub Actions: `check`(typecheck·lint·vitest·build·check:bundle)와 `e2e`(Chromium). 첫 푸시 때 실제 동작 확인이 아직 남아 있습니다.
- 마이그레이션을 추가한 뒤에는 떠 있는 `npm run dev`를 끄고 e2e를 돌려야 새 표가 적용됩니다.

### 개발 규칙

- 새 화면은 `App.tsx`에서 직접 import하지 말고 `src/web/lazyScreens.ts`에 등록합니다(화면 단위 지연 로딩).
- 모임 안의 쓰기 API는 `runMutation`(권한 검사·요청 ID 중복 방지·원자 저장)을 거칩니다. 화면의 쓰기 호출은 `mutate()`가 같은 요청 ID로 재시도합니다. 요청 ID는 필수입니다.
- 이름 대응: 화면 "티어" = 코드·DB `skillGroup`/`skill_group`, "서포터 횟수" = `rotation`, "칭호" = `titleBands`(등급은 `titleGrade` 1~8).
- 전적 글은 어디서나 `승률% · N승 M패 (G경기)` 꼴로 씁니다(정수 승률).
- 긴 안내문은 화면에 한 줄만 두고 나머지는 `Help`(접힌 도움말)에 넣습니다. 화면당 주 버튼(`primary`)은 하나입니다.
- 서식 도구(Prettier)는 쓰지 않습니다. 기존 파일의 줄 길이(약 120자)를 따릅니다.
- 타입 검사는 TypeScript 7, ESLint는 아직 7을 읽지 못해 5.9(`typescript-for-eslint` 별칭)를 씁니다.

### 배포(요약)

`docs/배포안내.md`가 기준입니다. 순서만 적으면: R2 버킷·staging D1 생성 → `wrangler secret put SESSION_SECRET --env staging|production` → `SITE_ADMIN_ACCOUNT_IDS`·`src/web/legal.ts`의 `[채워야 함]` 4개 → `npm run deploy:staging`·마이그레이션 0001~0025·확인 → `npm run deploy:production`. 배포 명령은 먼저 `scripts/predeploy-check.mjs`로 자리 표시값(`REPLACE-WITH-…`)과 production의 `[채워야 함]`을 검사해 남아 있으면 멈춥니다. wrangler 명령을 손으로 칠 때는 **항상 `--env staging|production`**(빠뜨리면 로컬 설정 `AUTH_MODE=fake`·D1 ID `0000…`이 올라가려 함. 공개 주소에서 가짜 로그인은 열리지 않게 막혀 있음). `SESSION_SECRET`을 바꾸면 자체 계정 비밀번호가 전부 무효가 됩니다(페퍼).

## 3. 구현한 것

### 경기 운영
- **참가자 고르기**: 10명 선택(11~20명은 먼저 고른 10명 + 대기자), 새 이름은 시작할 때 참가자로 등록, 지난 참가자·지난 내전 참가자 그대로 불러오기(실시간 경기가 없으면 마지막 확정 경기, 가져온 기록 포함), 참가 신청 링크(로그인 없는 신청, 본인 연결자는 "본인 확인됨")
- **준비 화면**: 블루팀·레드팀 판, 두 사람 차례로 누르기 또는 **끌어다 놓기**로 자리 바꾸기(대기자와도), 포지션 고정, 같은 팀·다른 팀 조건, 되돌리기 5단계 + 다시 앞으로, 대기자 교체, **예상 승률 판**(블루:레드 예상 승률과 한 줄 요약, 라인마다 두 사람의 MMR·라인 승률·우위 칩·맞대결 전적, 맨 아래 접힌 티어 점수), 명단 복사·편성 이미지, 같은 편성 경고. 탑·정글·미드·원딜·서폿은 글자와 아이콘에 라인마다 다른 색. PC에서는 편성 판이 따라 내려오고 섞기 버튼이 바로 옆에 있음
- **섞기**: 팀·라인 모두 섞기(같은 티어는 양 팀에 고르게), 균형 팀 추천 3개(최근 8경기 같은 팀 반복 회피. 추천 창은 후보마다 요약 칩 + 블루·레드 두 열 명단, 이름 옆 티어 알약), 라인만 섞기, 라인 섞기 + 서폿 돌아가며, 서포터만 바꾸기(아직 안 간 사람 중에서), 진영 바꾸기·진영 랜덤. 기피 라인을 피하고 못 피하면 알림
- **서포터 횟수**: 실제 시작한 경기만 셈, 주기(새 내전·초기화) 단위, "언제부터 세는지" 표시, 직접 고치기, 초기화
- **경기 시작 → 결과 입력**(블루팀 승/레드팀 승 큰 버튼, 진영 정정 접힘) → 다음 경기 준비(같은 팀·포지션 유지·시리즈로 이어가기). 진행 중 교체, 참가자에게 편성 보내기(`#/v/토큰/live`), 미진행 취소
- **정정·메모·시리즈**: 승리 팀·진영·포지션·참가자·시각 정정, 전적 제외·복구, 변경 내역, 200자 메모, 3판 2선승·5판 3선승·자유 시리즈

### 팀 편성 도구(운영자 기준)
- **티어 배정**(1~5티어·미지정, 기록으로 제안받기, 티어 점검), **기피 라인**(최대 4개, 멤버가 자기 것 직접 정할 수 있음). 화면은 머리가 따라오고 PC에서는 측면 요약 판
- 티어 공개 여부, 팀 추천 다양성 설정, **MMR 설정**(모임 탭 > 기록 관리): 배치 경기 수(기본 10, 1~30. 칭호·MMR K·랭킹 묶음·예상 신뢰 판정이 모두 따름), 시작 점수(기본 1200, 600~3000), 배치 중 K(기본 50, 1~100), 배치 뒤 K(기본 30, 1~100)

### 전적·통계
- **기록**: 경기 카드, 사람·승패·진영 거르기, 범위(오늘·시즌·연도·전체), CSV 내려받기
- **날짜 점검**(`#/dates`): 입력 순서와 견줘 연도가 밀린 묶음·같은 시각(열 명이 같으면 중복 가능)·미래 날짜를 찾고, 묶음이나 경기 번호 범위의 연도를 ±1 한 번에 옮김(경기마다 정정 기록). 시트·기존 사이트 가져오기 확인 단계에도 같은 경고
- **랭킹**: 기록 화면 안 소환사 랭킹(승률·경기 수·승수·MMR 순, 라인별, 누적 50경기 이상 먼저, 최근 승패·연승) + 상단 **랭킹 탭**(2026-11-09, `#/ranking`): MMR 순위표 전용 화면. 1위·최근 10경기 최고 상승·최고 MMR 타일, 순위·칭호·MMR·최근 변화·누적 전적·최고 MMR·최근 10경기, 행을 펼치면 MMR 추이. 조회 링크·예시 모임 메뉴에도 있음

### 이변·공정성·참석·그래프(2026-11-09 추가)
Riot API 없이도 쌓인 승패·MMR·세션만으로 더 보여 주려고 넣은 것들입니다. 모두 화면에서 계산하며 서버·DB는 바뀌지 않았습니다.
- **이변 지수**: 경기 직전 팀원 MMR 평균으로 예상 승률을 구하고, 이긴 팀의 예상이 40% 미만이면 "이변". 경기 상세에 "경기 전 예상 블루 62% : 레드 38%", 경기 카드에 이변 배지, 개인 통계에 이변 승 횟수·약팀일 때 승률, 시즌 시상에 "이변 메이커". 열 명 모두 배치(배치 경기 수, 기본 10) 전이면 예상만 보이고 이변 판정은 하지 않습니다

## 5. 유의사항

### 검증 범위
- 모든 검증은 **로컬**(Workers 로컬 런타임 + 로컬 D1, 헤드리스 Chromium·WebKit)에서 했습니다. 운영 D1, 실기기, 실제 OAuth는 미확인입니다.
- 자체 계정 비밀번호 해시가 무료 요금제 CPU 한도에 걸리면 `PASSWORD_PBKDF2_ITERATIONS`를 낮추거나 유료 요금제를 씁니다.
- 큰 모임의 **백업 복원**은 무료 요금제에서 CPU 초과(1102)로 끊길 수 있습니다(staging에서 522경기로 측정 예정). 운영에 기존 기록을 처음 옮길 때는 '기존 사이트 기록 가져오기'(50경기씩)를 씁니다(`docs/배포안내.md` 8-1·13절).

### 사용할 때 알아 둘 동작
- **티어는 기본 비공개**(운영자만). 미지정은 "못하는 사람"이 아니라 "아직 안 정한 사람"입니다.
- "직전 편성으로"는 최근 5단계까지, "다시 앞으로"는 바로 앞 한 단계. 다른 사람·대기자로 교체하면 되돌리기 이력은 비워집니다.
- 대기자는 이 기기에만 있고 경기 기록에 들어가지 않습니다.
- 서포터 횟수는 "이 팀으로 시작"한 경기만 세고, 새 내전 시작(12시간 공백 뒤 물어봄)이나 초기화 뒤에 시작한 경기부터 다시 셉니다. 이전 경기 기록은 그대로입니다.
- 진행 중인 경기의 명단은 교체 기능으로만 바꿀 수 있고, 아니면 미진행 취소 후 다시 시작합니다.
- 자체 계정은 이메일을 받지 않습니다. **복구 코드를 적어 두지 않고 비밀번호를 잊으면 계정을 되찾을 수 없습니다.** 로그아웃하면 모든 기기에서 로그아웃됩니다.
- 구글 시트는 읽기만 하며 비공개 시트는 읽지 못합니다. 여기서 저장해도 원본 시트는 바뀌지 않습니다.
- **참가 신청 링크의 익명 신청은 본인 확인을 하지 않습니다.** 링크가 퍼졌으면 "링크 다시 만들기"나 "신청 닫기"를 씁니다. 신청 목록은 경기를 시작해도 지워지지 않고 백업에는 들어가지 않습니다.
- **경기 메모와 시리즈는 공개 정보**(조회 링크에서도 보임)입니다. 시리즈에는 두 팀 5명 구성이 같은 경기만 넣을 수 있고 통계는 판 단위입니다.
- **예상 승률·이변·공정성은 누적 MMR이 전제**입니다. 새 모임이나 연결 안 된 임시 이름이 많은 날은 예상이 50% 근처에 머물고 "정확하지 않아요"가 뜹니다. 경기가 쌓이면 자연히 맞아 들어갑니다. 임계값(이변 40%, 균형 ±5%p, 라인 우위 MMR 차 25)은 임시값이라 바꿀 수 있습니다(`src/shared/upset.ts`, `forecast.ts`).
- **배치 경기 수·MMR 시작 점수·K를 바꾸면 지난 경기까지 전부 다시 계산**됩니다(저장하는 값이 아니라 매번 계산하므로). 그 자리에서 칭호가 붙거나 사라지고 MMR·티어·랭킹 묶음·이변 판정이 달라질 수 있습니다. 시작 점수는 모든 점수를 같이 옮길 뿐이라 순위·예상 승률은 그대로이고 숫자와 티어 이름표만 바뀝니다.
- MMR 티어 이름은 Riot Games의 리그 오브 레전드 시즌 2 Elo 구간 이름을 빌린 것이며 Riot 공식 등급이 아닙니다. 모임 안에서 계산한 내전 점수의 구간 표시일 뿐입니다.
- 참석 통계의 출석률은 "그 사람이 처음 온 날부터"가 분모입니다. 가입 전 날을 결석으로 치지 않기 위해서입니다.
- 시즌 시상 기준: 최고 승률은 모임 전체 **누적** 50경기 이상인 사람 중 고른 범위 안 승률 1위(랭킹의 "누적 50경기 이상" 묶음과 같음. 범위 안 경기 수는 따지지 않음), 라인별 최고 승률은 누적 50경기 이상이면서 범위 안 그 라인 5경기 이상, 가장 많이 성장 두 범위 모두 10경기 이상, 듀오·천적 5경기 이상. 해당 없는 상은 시상 맨 아래 "기준 미달" 한 줄로 모음.
- 모임 수 한도(대표 + 공동 운영 5개)는 만들기·복원·넘겨받기·초대 수락에 모두 적용됩니다.
- **참가자 연결은 백업에 들어가지 않습니다**(계정 정보). 익명 처리는 되돌릴 수 없지만 그 전 백업으로 복원하면 이름이 돌아옵니다(서버 자동 백업에도 최대 30일 옛 이름이 남음. 모임 삭제 때는 자동 백업도 함께 지움). 합치기를 되돌리면 옮긴 본인 연결도 원래 사람에게 돌아오지만, 2026-11-08 전에 한 합치기와 백업에서 복원한 합치기는 연결 기록이 없어 돌아가지 않습니다(되돌린 뒤 확인하라고 안내).
- 공동 운영자를 내보내는 순간과 거의 동시에 들어온 그 계정의 쓰기 하나는 저장될 수 있습니다.

### 결정이 필요한 것
- **기존 기록의 연도**: 기존 사이트에서 가져온 522경기 중 일부는 저장된 연도가 틀렸을 가능성이 있습니다. 모임 시작 시점 확인이 필요합니다(`docs/구현현황.md`).
