# 내전 운영 서비스 v2 (naejeon-v2)

리그 오브 레전드 5:5 내전 모임을 위한 팀 편성·전적 기록 사이트입니다.
개인이 여는 사용자 설정 게임은 Riot 서버에 기록이 남지 않으므로, 운영자가 직접 입력한 승패·라인·진영으로 전적을 쌓습니다.

- 최종 갱신: 2026-11-06
- 상태: **로컬에서만 검증됨. 아직 배포하지 않았습니다.**
- 자세한 기록: [`docs/구현현황.md`](docs/구현현황.md) · 배포 순서: [`docs/배포안내.md`](docs/배포안내.md)

## 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 서버 | Cloudflare Workers + Hono, D1(SQLite) |
| 화면 | React 19 + Vite, 별도 UI 라이브러리 없음(CSS 토큰) |
| 테스트 | Vitest(단위·통합), Playwright(브라우저 흐름) |
| 언어 | TypeScript |

폴더: `src/server`(API), `src/shared`(서버·화면 공용 순수 로직), `src/web`(화면), `migrations`(DB), `test`(단위·통합), `e2e`(브라우저), `docs`(설계·현황).

## 실행 방법

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치(버전 고정) |
| `npm run dev` | 화면 빌드 → 로컬 DB 마이그레이션 → 로컬 서버 `http://127.0.0.1:8787` |
| `npm run typecheck` | 서버·화면 타입 검사 |
| `npx vitest run --testTimeout=30000` | 단위·통합 테스트 |
| `npm run e2e` | 브라우저 흐름 테스트 |
| `npm run seed` | 떠 있는 로컬 서버에 합성 데이터(가짜 이름 30명, 경기 120개) 넣기 |

로컬 로그인은 개발용 가짜 로그인입니다(`AUTH_MODE=fake`). 로컬 비밀값은 `.dev.vars`에 두며 git에 올라가지 않습니다.

## 구현한 것

### 경기 운영
- **참가자 고르기**: 10명 선택, 지난 참가자 불러오기, 누적 경기 수·최근 참가 표시
- **참가 신청 링크**: 운영자가 링크를 보내면 참가자가 로그인 없이 "오늘 참가"를 누름(명단의 자기 이름 또는 새 이름, 최대 30명). 고르기 화면의 "신청자 N명 불러오기"가 신청 순 앞 10명을 고르고 나머지는 대기로 표시. 열기·닫기, 링크 다시 만들기, 한 사람 지우기, 신청 비우기
- **준비 화면**: 두 팀 편성, 두 사람 자리 바꾸기, 포지션 고정, 좌우 바꾸기, 직전 편성으로 되돌리기
- **진영 고르기**: 팀 A 블루/레드/나중에 정하기, 진영 랜덤
- **경기 시작 → 결과 입력**: 한 요청·한 트랜잭션으로 시작, 결과 입력 3단계, 미진행 취소
- **정정**: 승리 팀·진영·포지션·참가자·경기 시각 정정, 전적 제외·복구, 변경 내역
- **다음 경기 준비**: 같은 팀으로 이어서, 포지션 유지

### 팀 편성 도구
- **우선순위 배정** (`#/priority`): 사람마다 1~4순위 또는 미지정을 운영자가 직접 정함
- **우선순위 제안**: 누적 10경기 이상인 사람의 승률로 순위 초안을 제안. 미리보기에서 고른 사람만 적용
- **순위 점검**: 우선순위 합이 높았던 팀의 실제 승률, 순위와 성적이 어긋나는 사람 표시(지금 순위를 지난 경기에 적용한 값)
- **기피 라인** (`#/priority/avoid`): 사람마다 못 가는 라인을 최대 4개 지정. 올랜덤이 그 라인을 피하고, 피할 수 없으면 알림. 직접 건 포지션 고정과 서포터 횟수 규칙이 기피보다 우선
- **팀·라인 모두 섞기**: 팀을 새로 나누고 라인도 섞음. 같은 순위끼리는 양 팀에 고르게 나뉨(순위마다 인원 차 1 이하)
- **라인만 섞기 · 라인 섞기 + 서폿 돌아가며**: 팀원은 그대로 두고 라인만 섞음. 뒤의 것은 서포터를 아직 안 간 사람으로 정함
- **팀 추천**: 우선순위 가중치 합이 비슷한 편성 3개 제안, 최근 8경기 같은 팀 반복을 피함
- **같은 팀·다른 팀 조건**: 팀 추천과 팀·라인 모두 섞기에 적용
- **서포터 횟수**: 이번 내전에서 서포터를 아직 안 간 사람 중에서만 뽑음, 팀별로 따로 판단, 횟수 직접 입력·초기화

### 전적·통계
- **기록**: 경기 카드(양 팀 10명·라인·승패), 사람·승패·진영으로 거르기, 범위(오늘·시즌·연도·전체)
- **랭킹**: 승률·경기 수·승수 정렬, 라인별 랭킹, 누적 50경기 이상인 사람을 먼저 표시
- **개인 통계**: 승률 고리, 최근 10·20경기, 라인별·진영별, 잘 맞는 동료·어려운 상대, 칭호
- **검색, 두 사람 비교, 그래프 분석, 홈 요약, 오늘의 결과**
- **결과 이미지**: 오늘의 결과·경기 한 건을 PNG로 공유·내려받기

### 기록 가져오기
- 표 붙여넣기 일괄 입력(50경기 묶음), 지난 경기 한 건 입력
- 구글 시트에서 가져오기(공개 시트, 열 맞추기, 다시 가져오면 새 줄만)
- 기존 사이트(v1) 기록 가져오기
- 중복 참가자 합치기·되돌리기

### 계정·모임 관리
- **로그인**: 자체 계정(아이디 + 비밀번호, 복구 코드), 카카오·Google(키가 있을 때만 버튼 표시)
- **공동 운영자**: 1회용 초대 링크(24시간), 최대 5명, 대표 전용 권한 분리
- **모임 고르기**: 한 계정이 대표·공동 운영을 합쳐 모임 5개까지. 모임 탭의 "내 모임"과 상단 계정 메뉴에서 바꾸고 기기에 기억. 작성 중인 편성·고른 참가자는 모임마다 따로. 이미 모임이 있어도 공동 운영자 초대를 수락할 수 있음, 새 모임 만들기
- **운영자 넘기기, 조회 링크(읽기 전용), 시즌, 칭호 설정**
- **백업 내려받기·복원, 모임 삭제·탈퇴**
- **보안**: 모든 쓰기의 공통 권한 검사·요청 ID 중복 방지, 요청 수 제한, Origin 확인

### 화면
- 테마 3종(다크·바이올렛·라이트), 320px~1440px 반응형, 좁은 화면은 하단 탭

## 유의사항

### 검증 범위
- 모든 검증은 **로컬**(로컬 Workers 실행 환경 + 로컬 D1, 헤드리스 Chromium)에서 했습니다.
- 확인하지 못한 것: 운영 D1에서의 동작, 실제 휴대폰·iOS Safari·화면 키보드, 실제 카카오·Google 연동.
- 자체 계정의 비밀번호 해시 계산이 Cloudflare 무료 요금제의 CPU 한도에 걸릴 수 있습니다. 배포 후 확인이 필요하며, 걸리면 `PASSWORD_PBKDF2_ITERATIONS`를 낮추거나 유료 요금제를 씁니다.

### 개발할 때
- 이 PC에서는 `npm test`의 기본 5초 제한이 부하로 초과될 수 있어 `--testTimeout=30000`을 붙입니다.
- **마이그레이션을 추가한 뒤에는 떠 있는 `npm run dev` 서버를 끄고** e2e를 돌려야 새 표가 적용됩니다.
- 마이그레이션 번호 0004는 비어 있습니다(0003 다음이 0005). 적용 순서에는 영향이 없습니다.
- 화면 이름 "우선순위"의 코드·DB 이름은 `skillGroup` / `skill_group`입니다. "서포터 횟수"의 코드 이름은 `rotation`입니다.

### 배포할 때
- wrangler 명령에는 **항상 `--env production`** 을 붙입니다. 빠뜨리면 로컬 설정(가짜 로그인)이 올라갑니다.
- 배포 전에 직접 해야 할 일: Cloudflare D1 생성·비밀값 등록·마이그레이션 적용, `src/web/legal.ts`의 `[채워야 함]` 4개와 개인정보 처리방침 검토(현재 **초안**). 카카오·Google 앱 등록은 선택입니다.
- Riot 제품 등록은 하지 않습니다. Riot API를 쓰지 않기 때문이며, 푸터의 "라이엇 게임즈와 무관" 고지 문구만 유지합니다.

### 사용할 때 알아 둘 동작
- **우선순위는 운영자만 봅니다.** 기본은 비공개이며 조회 링크에는 나가지 않습니다. 미지정은 "못하는 사람"이 아니라 "아직 안 정한 사람"입니다.
- "직전 편성으로"는 한 단계만 되돌립니다.
- "서포터만 바꾸기"를 같은 조건에서 다시 누르면 새로 뽑지 않고 같은 결과를 유지합니다.
- 진행 중인 경기의 명단은 고칠 수 없습니다. 미진행 취소 후 다시 시작합니다.
- 자체 계정은 이메일을 받지 않습니다. **복구 코드를 적어 두지 않고 비밀번호를 잊으면 계정을 되찾을 수 없습니다.**
- 로그아웃하면 그 계정의 모든 기기에서 로그아웃됩니다.
- 비공개 구글 시트는 읽지 못합니다.
- 공동 운영자를 내보내는 순간과 거의 동시에 들어온 그 계정의 쓰기 요청 하나는 저장될 수 있습니다.
- **참가 신청 링크는 본인 확인을 하지 않습니다.** 링크를 가진 사람은 누구의 신청이든 넣고 뺄 수 있습니다. 링크가 퍼졌으면 "링크 다시 만들기"(이전 링크 무효)나 "신청 닫기"를 씁니다.
- 신청 링크 주소는 서버에 저장되어 운영자·공동 운영자 누구나 어느 기기에서든 다시 복사할 수 있습니다. "링크 다시 만들기"를 누르면 이전에 보낸 링크는 열리지 않습니다. DB가 유출되면 신청 링크도 함께 노출됩니다(이 링크의 권한은 참가 신청뿐입니다).
- 신청 목록은 경기를 시작해도 지워지지 않습니다(같은 날 여러 판). 운영자가 "신청 비우기"로 지웁니다. 백업 파일에는 들어가지 않고, 백업에서 복원하면 비워집니다.
- 모임 수 한도(대표 + 공동 운영 합계 5개)는 모임 만들기·백업으로 새 모임·운영자 넘겨받기·공동 운영자 수락에 모두 적용됩니다.

### 결정이 필요한 것
- **기존 기록의 연도**: 기존 사이트에서 가져온 522경기 중 일부는 저장된 연도가 틀렸을 가능성이 있습니다. 모임이 언제 시작했는지 확인이 필요합니다(`docs/구현현황.md`의 "남은 것").

### 만들지 않은 것
- 챔피언·KDA·CS 통계, Riot 계정 전적 조회(내전은 Riot 기록에 남지 않음)
- 내전 라운지, 참가자 계정 연결, 실시간 갱신
