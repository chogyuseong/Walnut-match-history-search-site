# 내전 운영 서비스 v2 (naejeon-v2)

리그 오브 레전드 5:5 내전 모임을 위한 팀 편성·전적 기록 사이트입니다.
개인이 여는 사용자 설정 게임은 Riot 서버에 기록이 남지 않으므로, 운영자가 직접 입력한 승패·라인·진영으로 전적을 쌓습니다.

- 최종 갱신: 2026-11-06
- 상태: **로컬에서만 검증됨. 아직 배포하지 않았습니다.**
- 자세한 기록: [`docs/구현현황.md`](docs/구현현황.md) · 배포 순서: [`docs/배포안내.md`](docs/배포안내.md)

## 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 서버 | Cloudflare Workers + Hono, D1(SQLite) |
| 화면 | React 19 + Vite, 별도 UI 라이브러리 없음(CSS 토큰) |
| 테스트 | Vitest(단위·통합), Playwright(브라우저 흐름) |
| 언어 | TypeScript |

폴더: `src/server`(API), `src/shared`(서버·화면 공용 순수 로직), `src/web`(화면), `migrations`(DB), `test`(단위·통합), `e2e`(브라우저), `docs`(설계·현황).

## 실행 방법

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치(버전 고정) |
| `npm run dev` | 화면 빌드 → 로컬 DB 마이그레이션 → 로컬 서버 `http://127.0.0.1:8787` |
| `npm run typecheck` | 서버·화면 타입 검사 |
| `npx vitest run --testTimeout=30000` | 단위·통합 테스트 |
| `npm run e2e` | 브라우저 흐름 테스트 |
| `npm run seed` | 떠 있는 로컬 서버에 합성 데이터(가짜 이름 30명, 경기 120개) 넣기 |
| `npx vitest run --config vitest.measure.config.ts --silent=false` | 떠 있는 로컬 서버로 운영자 스냅숏 크기·통계 계산 시간 측정(경기 500·2000·5000개) |

로컬 로그인은 개발용 가짜 로그인입니다(`AUTH_MODE=fake`). 로컬 비밀값은 `.dev.vars`에 두며 git에 올라가지 않습니다.

## 구현한 것

### 경기 운영
- **참가자 고르기**: 10명 선택, 지난 참가자 불러오기, 누적 경기 수·최근 참가 표시
- **참가 신청 링크**: 운영자가 링크를 보내면 참가자가 로그인 없이 "오늘 참가"를 누름(명단의 자기 이름 또는 새 이름, 최대 30명). 고르기 화면의 "신청자 N명 불러오기"가 신청 순 앞 10명을 고르고 나머지는 대기로 표시. 열기·닫기, 링크 다시 만들기, 한 사람 지우기, 신청 비우기
- **준비 화면**: 왼쪽 블루팀·오른쪽 레드팀(진영 색 테두리), 두 사람 자리 바꾸기, 포지션 고정, 진영 바꾸기(블루팀 5명과 레드팀 5명을 맞바꿈), 직전 편성으로 되돌리기
- **진영**: 준비 화면은 늘 블루팀·레드팀, 진영 랜덤(반반으로 두 팀을 맞바꿈). 진영이 정해진 경기는 어느 화면에서나 블루팀·레드팀으로, 진영 미상 경기는 팀 A·팀 B로 표시
- **경기 시작 → 결과 입력**: 한 요청·한 트랜잭션으로 시작, 결과 입력 3단계, 미진행 취소
- **정정**: 승리 팀·진영·포지션·참가자·경기 시각 정정, 전적 제외·복구, 변경 내역
- **다음 경기 준비**: 같은 팀으로 이어서, 포지션 유지, 시리즈로 이어가기
- **경기 메모**: 경기마다 200자 메모(결과 입력 창·경기 상세에서 쓰고 고침). 카드·상세·조회 링크에 보임
- **시리즈 묶음**: 3판 2선승·5판 3선승·자유. 결과 저장 뒤 "시리즈로 이어가기"나 기록·경기 상세에서 묶음. 같은 사람들로 이뤄진 팀 기준 점수("결승 · 3판 2선승 · 2:1"), 카드 배지, 기록의 시리즈 목록

### 팀 편성 도구
- **티어 배정** (`#/priority`): 사람마다 1~4티어 또는 미지정을 운영자가 직접 정함
- **티어 제안**: 누적 10경기 이상인 사람의 승률로 티어 초안을 제안. 미리보기에서 고른 사람만 적용
- **티어 점검**: 티어 점수 합이 높았던 팀의 실제 승률, 티어와 성적이 어긋나는 사람 표시(지금 티어를 지난 경기에 적용한 값)
- **기피 라인** (`#/priority/avoid`): 사람마다 못 가는 라인을 최대 4개 지정. 섞기가 그 라인을 피하고, 피할 수 없으면 알림. 직접 건 포지션 고정과 서포터 횟수 규칙이 기피보다 우선
- **팀·라인 모두 섞기**: 팀을 새로 나누고 라인도 섞음. 같은 티어끼리는 양 팀에 고르게 나뉨(티어마다 인원 차 1 이하)
- **라인만 섞기 · 라인 섞기 + 서폿 돌아가며**: 팀원은 그대로 두고 라인만 섞음. 뒤의 것은 서포터를 아직 안 간 사람으로 정함
- **팀 추천**: 티어 가중치 합이 비슷한 편성 3개 제안, 최근 8경기 같은 팀 반복을 피함
- **같은 팀·다른 팀 조건**: 팀 추천과 팀·라인 모두 섞기에 적용
- **서포터 횟수**: 이번 내전에서 서포터를 아직 안 간 사람 중에서만 뽑음, 팀별로 따로 판단, 횟수 직접 입력·초기화

### 전적·통계
- **기록**: 경기 카드(양 팀 10명·라인·승패), 사람·승패·진영으로 거르기, 범위(오늘·시즌·연도·전체)
- **랭킹**: 승률·경기 수·승수 정렬, 라인별 랭킹, 누적 50경기 이상인 사람을 먼저 표시
- **개인 통계**: 승률 고리, 최근 10·20경기, 라인별·진영별, 잘 맞는 동료·어려운 상대, 칭호
- **검색, 두 사람 비교, 그래프 분석, 홈 요약, 오늘의 결과**
- **결과 이미지**: 오늘의 결과·경기 한 건을 PNG로 공유·내려받기
- **시즌 요약과 시상** (`#/season/시즌ID`, `#/season/year/2026`): 경기·참가자·진영 승률·내전한 날, 최고 승률·최다 승·개근상·최장 연승·라인별 최고 승률·최고의 듀오·천적 관계·가장 많이 성장·헌신상(근거 숫자, 동률 공동 수상, 기준 미달은 해당 없음). 이미지·텍스트로 공유, 조회 링크에서도 열림

### 기록 가져오기
- 표 붙여넣기 일괄 입력(50경기 묶음), 지난 경기 한 건 입력
- 구글 시트에서 가져오기(공개 시트, 열 맞추기, 다시 가져오면 새 줄만)
- 기존 사이트(v1) 기록 가져오기
- 중복 참가자 합치기·되돌리기

### 계정·모임 관리
- **로그인**: 자체 계정(아이디 + 비밀번호, 복구 코드), 카카오·Google(키가 있을 때만 버튼 표시)
- **공동 운영자**: 1회용 초대 링크(24시간), 최대 5명, 대표 전용 권한 분리
- **모임 고르기**: 한 계정이 대표·공동 운영을 합쳐 모임 5개까지. 모임 탭의 "내 모임"과 상단 계정 메뉴에서 바꾸고 기기에 기억. 작성 중인 편성·고른 참가자는 모임마다 따로. 이미 모임이 있어도 공동 운영자 초대를 수락할 수 있음, 새 모임 만들기
- **운영자 넘기기, 조회 링크(읽기 전용), 시즌, 칭호 설정**
- **백업 내려받기·복원, 모임 삭제·탈퇴**
- **보안**: 모든 쓰기의 공통 권한 검사·요청 ID 중복 방지, 요청 수 제한, Origin 확인

### 참가자가 직접 하는 것 (참가자 본인 연결)
원칙: "참가자는 자기 것만 건드리고, 기록은 운영자만 고친다".
- **본인 연결**: 운영자(대표·공동)가 모임 탭 참가자 '수정'에서 1회용 연결 링크(24시간, 해시만 저장)를 만들어 보내면, 본인이 로그인해 `#/claim/토큰`에서 확인하고 자기 이름과 계정을 묶음. 한 참가자에 계정 하나, 한 계정은 한 모임에서 이름 하나, 계정당 연결 20곳까지(운영 모임 한도 5와 따로). 운영자·본인 모두 끊을 수 있음
- **참가 중인 모임** (`#/mine/모임ID`): 계정 메뉴·모임 탭의 "참가 중인 모임"에서 열면 조회 링크와 같은 읽기 전용 화면이 토큰 없이 열림. 첫 화면 "내 정보": 내 전적 바로 가기, 현재 경기의 내 자리
- **내 기피 라인**: 멤버가 자기 것만 정함(최대 4개). 운영자 기피 라인 화면에 "본인이 정함", 운영자가 고치면 표시가 사라짐
- **본인 확인 참가 신청**: 멤버가 로그인한 채 신청 링크에서 자기 이름으로 신청하면 "본인 확인됨". 그 신청은 본인과 운영자만 뺄 수 있음. 익명 신청은 예전 그대로
- **요청**: 자기가 뛴 경기의 결과 정정 요청, 내 기록 삭제·익명 처리 요청(200자, 열린 요청 5개까지). 기록은 바뀌지 않고 운영자가 모임 탭 "참가자 요청"에서 처리함·반려 + 짧은 답. 멤버는 자기 요청의 상태와 답만 봄
- **익명 처리** (운영자): 이름을 "탈퇴한 참가자 N"으로, 보관, 연결·기피 라인·티어·요청·신청 정리. 경기 기록·통계는 그대로. 확인 문구 '익명', 되돌릴 수 없음

### 처음 온 사람 · 서비스 운영
- **첫 화면 소개**: 로그인하지 않았고 이 기기에 기억한 모임·조회 링크·편성이 없는 방문자에게 첫 화면 위에 사이트 소개와 "시작하기"(로그인·가입), "예시 모임 둘러보기". 로그인 없이 팀 짜기는 그 아래에서 그대로
- **예시 모임** (`#/demo`): 서버·DB 없이 기기에서 만든 합성 데이터(가짜 이름 24명, 경기 약 100개, 시즌 2개, 메모·시리즈 약간)를 조회 링크와 같은 화면(요약·검색·기록·랭킹·개인 통계·그래프·시즌 요약)으로 보여 줌. 티어·기피 라인 없음. 예시 데이터 코드는 그 화면을 열 때만 불러옴
- **오류 수집**: 화면 오류(전역 오류·처리 안 된 거절·화면 그리기 오류)와 서버의 예상하지 못한 오류를 가린 값으로 기록(계정·IP·쿠키·본문·참가자 이름 저장 안 함, 최근 1000건·30일). 화면 그리기 오류는 "문제가 생겼어요 · 새로 고침" 화면
- **사이트 현황** (`#/admin`): 사이트 운영자(`SITE_ADMIN_ACCOUNT_IDS`)만. 전체 계정·모임·경기·참가자 수, 최근 7일·30일 활동, 오류 목록(묶음·건수·스택), 요청 수 제한에 걸린 횟수, 오류 기록 비우기. 모임 안의 자료는 보이지 않음

## 유의사항

### 검증 범위
- 모든 검증은 **로컬**(로컬 Workers 실행 환경 + 로컬 D1, 헤드리스 Chromium)에서 했습니다.
- 확인하지 못한 것: 운영 D1에서의 동작, 실제 휴대폰·iOS Safari·화면 키보드, 실제 카카오·Google 연동.
- 자체 계정의 비밀번호 해시 계산이 Cloudflare 무료 요금제의 CPU 한도에 걸릴 수 있습니다. 배포 후 확인이 필요하며, 걸리면 `PASSWORD_PBKDF2_ITERATIONS`를 낮추거나 유료 요금제를 씁니다.

### 개발할 때
- 이 PC에서는 `npm test`의 기본 5초 제한이 부하로 초과될 수 있어 `--testTimeout=30000`을 붙입니다.
- **마이그레이션을 추가한 뒤에는 떠 있는 `npm run dev` 서버를 끄고** e2e를 돌려야 새 표가 적용됩니다.
- 마이그레이션 번호 0004는 비어 있습니다(0003 다음이 0005). 적용 순서에는 영향이 없습니다. 마지막은 0019(참가자 본인 연결·요청)입니다.
- 화면 이름 "티어"의 코드·DB 이름은 `skillGroup` / `skill_group`입니다. "서포터 횟수"의 코드 이름은 `rotation`입니다.

### 배포할 때
- 사이트 운영자는 `env.production.vars.SITE_ADMIN_ACCOUNT_IDS`에 계정 ID로 정합니다(비어 있으면 아무도 현황 화면을 못 봄). 로컬에서는 개발용 로그인 이름 `e2e-site-admin`이 사이트 운영자입니다(`docs/배포안내.md` 14절).
- 사고가 나면: 한 모임은 그 모임의 "백업에서 복원", 서비스 전체는 D1 Time Travel(무료 7일, DB 전체가 되돌아감). 절차는 `docs/배포안내.md` 13절.
- wrangler 명령에는 **항상 `--env production`** 을 붙입니다. 빠뜨리면 로컬 설정(가짜 로그인)이 올라갑니다.
- 배포 전에 직접 해야 할 일: Cloudflare D1 생성·비밀값 등록·마이그레이션 적용, `src/web/legal.ts`의 `[채워야 함]` 4개와 개인정보 처리방침 검토(현재 **초안**). 카카오·Google 앱 등록은 선택입니다.
- Riot 제품 등록은 하지 않습니다. Riot API를 쓰지 않기 때문이며, 푸터의 "라이엇 게임즈와 무관" 고지 문구만 유지합니다.

### 사용할 때 알아 둘 동작
- **티어는 운영자만 봅니다.** 기본은 비공개이며 조회 링크에는 나가지 않습니다. 미지정은 "못하는 사람"이 아니라 "아직 안 정한 사람"입니다.
- "직전 편성으로"는 한 단계만 되돌립니다.
- "서포터만 바꾸기"는 누를 때마다 아직 서포터를 안 간 사람 중에서 새로 뽑습니다. 안 간 사람이 둘 이상이면 누를 때마다 바뀝니다.
- 진행 중인 경기의 명단은 고칠 수 없습니다. 미진행 취소 후 다시 시작합니다.
- 자체 계정은 이메일을 받지 않습니다. **복구 코드를 적어 두지 않고 비밀번호를 잊으면 계정을 되찾을 수 없습니다.**
- 로그아웃하면 그 계정의 모든 기기에서 로그아웃됩니다.
- 비공개 구글 시트는 읽지 못합니다.
- 공동 운영자를 내보내는 순간과 거의 동시에 들어온 그 계정의 쓰기 요청 하나는 저장될 수 있습니다.
- **참가 신청 링크의 익명 신청은 본인 확인을 하지 않습니다.** 링크를 가진 사람은 익명 신청이면 누구의 것이든 넣고 뺄 수 있습니다(연결된 이름으로 남이 익명 신청하는 것도 받습니다). 본인과 연결한 참가자가 로그인한 채 신청한 것만 "본인 확인됨"이라 본인과 운영자만 뺄 수 있습니다. 링크가 퍼졌으면 "링크 다시 만들기"(이전 링크 무효)나 "신청 닫기"를 씁니다.
- 신청 링크 주소는 서버에 저장되어 운영자·공동 운영자 누구나 어느 기기에서든 다시 복사할 수 있습니다. "링크 다시 만들기"를 누르면 이전에 보낸 링크는 열리지 않습니다. DB가 유출되면 신청 링크도 함께 노출됩니다(이 링크의 권한은 참가 신청뿐입니다).
- 신청 목록은 경기를 시작해도 지워지지 않습니다(같은 날 여러 판). 운영자가 "신청 비우기"로 지웁니다. 백업 파일에는 들어가지 않고, 백업에서 복원하면 비워집니다.
- **경기 메모와 시리즈는 공개 정보입니다.** 조회 링크에서도 보입니다. 메모 수정은 "변경 내역"에 남지 않습니다.
- 시리즈에는 두 팀의 5명 구성이 같은 경기만 넣을 수 있습니다(진영은 달라도 됨). 통계(승률·랭킹)는 지금처럼 판 단위로 세고, 시리즈는 묶어서 보여 주기만 합니다. 형식의 승수를 채운 뒤 더 넣는 것은 막지 않고 경고만 합니다.
- 시즌 요약의 시상 기준: 최고 승률·가장 많이 성장 10경기 이상, 라인별 최고 승률 그 라인 5경기 이상, 듀오·천적 5경기 이상. 티어·기피 라인은 쓰지 않습니다.
- 모임 수 한도(대표 + 공동 운영 합계 5개)는 모임 만들기·백업으로 새 모임·운영자 넘겨받기·공동 운영자 수락에 모두 적용됩니다.
- **참가자 연결은 백업 파일에 들어가지 않습니다**(계정 정보). 백업에서 복원해도 그 참가자가 복원한 기록에 남아 있으면 연결·요청은 유지되고, 없어지면 지워집니다. 중복 참가자 합치기는 연결을 남은 사람에게 옮기고(남은 사람이 이미 연결돼 있으면 합쳐진 쪽 연결은 지움), 되돌려도 연결은 돌아가지 않습니다.
- **익명 처리는 되돌릴 수 없지만**, 그 전에 내려받은 백업으로 복원하면 옛 이름이 돌아옵니다. 경기 메모에 직접 적은 이름은 자동으로 지우지 않습니다(처리 뒤 해당 경기 번호를 알려 줌).
- 멤버가 바꾼 기피 라인·요청은 운영자 화면을 다시 불러오거나(새로 고침·다른 화면에서 돌아옴) 해야 보입니다(실시간 갱신 없음).

### 결정이 필요한 것
- **기존 기록의 연도**: 기존 사이트에서 가져온 522경기 중 일부는 저장된 연도가 틀렸을 가능성이 있습니다. 모임이 언제 시작했는지 확인이 필요합니다(`docs/구현현황.md`의 "남은 것").

### 만들지 않은 것
- 챔피언·KDA·CS 통계, Riot 계정 전적 조회(내전은 Riot 기록에 남지 않음)
- 내전 라운지, 실시간 갱신, 알림 발송
- 참가자의 경기 입력·정정, 다른 사람 정보 수정, 참가자끼리의 메시지·댓글(참가자는 자기 것만 고치고 기록은 요청만 함)
