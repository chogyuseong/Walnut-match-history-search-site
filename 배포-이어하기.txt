[회사 컴퓨터에서 처음 할 일]

1. 저장소 받기
     git pull
     npm ci
2. Cloudflare 로그인(배포하거나 wrangler 명령을 쓸 때만 필요)
     npx wrangler login
3. 로컬 개발 서버를 띄우려면 저장소 맨 위에 .dev.vars 파일을 만들고 한 줄을 넣는다(git에 안 올라가는 파일).
     SESSION_SECRET=아무거나32자이상인무작위문자열
   PASSWORD_PEPPER는 wrangler.jsonc 맨 위에 로컬 전용 값이 이미 있다.
   그 뒤 npm run dev → http://localhost:8787
4. 테스트: npm test(단위), npm run e2e(브라우저)

[남은 일 (모두 직접)]

1. 휴대폰과 카카오톡 안 브라우저에서 운영 주소 열어 보기.
2. Cloudflare 계정과 GitHub 계정에 2단계 인증 켜기. 감사에서 가장 큰 단일 위험으로 꼽은 항목이다.
3. staging에 시험 계정·모임이 남아 있다(522경기 복원 시험 모임 포함). 필요 없으면 지운다.


[정해 둔 것]

- 요금제는 무료. 이용자 수를 보고 Paid(월 5달러)로 올린다.
  무료는 한도를 넘으면 돈이 나가지 않고 그날 한국 시각 오전 9시까지 멈춘다.
- 가입 코드는 넣지 않았다. 이용자 수를 보고 정한다.
- 로그인은 자체 계정만. 카카오·구글은 나중에.


[지켜볼 것]

- Cloudflare 대시보드의 D1 하루 읽기 행 수. 300만 행을 넘는 날이 생기면 Paid 전환이나 스냅숏 캐시를 검토한다.
  큰 모임(522경기)은 저녁 한 번에 하루 읽기 한도의 약 40%를 쓴다.
- 대시보드 로그에 1102 오류가 보이기 시작하면 그날 Paid로 바꾼다(CPU 한도. staging 실측은 10ms를 넘지만 끊긴 적은 없다).
- 새 모임의 큰 기록을 옮길 때는 그날만 wrangler.jsonc 운영 구역의 RATE_BULK_ROWS_PER_ACCOUNT를 올려 배포한다.


[참고]

- 배포는 npm run deploy:staging → 확인 → npm run deploy:production 순서. 맨손 wrangler deploy는 쓰지 않는다.
- 비밀값 등록(wrangler secret put)은 Claude 권한으로 막혀 있어 직접 실행한다.
- 흔한 비밀번호 목록(src/shared/account.ts)에 walnut12, faker123 같은 이 사이트에 맞춘 값도 있다.
- 새 비밀번호는 10자 이상. 모임 삭제·대표 넘기기·백업 복원은 비밀번호를 다시 넣어야 한다.
